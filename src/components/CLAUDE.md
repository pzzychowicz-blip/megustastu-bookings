- **ClashBanner.jsx** — v17.11.0 — DOUBLE-BOOKINGS, one row per clashing PAIR. The app had a conflict detector and a conflict-shaped banner that were about different things: `overlapWarnings` is an OVERSTAY detector (it iterates SEATED bookings), so two *confirmed* bookings on one table never reached it, and `findConflicts` — which does see them — was wired only to the silent reconciler, which relocates the newest NON-LOCKED booking and then gives up. An all-locked clash was therefore detected, deliberately left alone, and shown to NOBODY, while being reachable by completely ordinary use (every walk-in and every drag-drop sets `_locked`). Measured live: 288px of overlap with the later block painting over the earlier, so the timeline drew a double-booking as two tidy consecutive sittings — the one place this app asserted something FALSE rather than merely omitting it. Its action is **Assign, not Reassign**: copying OverlapBanner's row would have shipped a button that can only ever fail, since `reassignBooking` refuses a locked booking and a surviving clash is locked BY DEFINITION. It offers the LATER booking, matching the reconciler's own newest-first tie-break so the automatic and manual paths propose the same move. Scoped to the VIEWED date (unlike late/overlap/waitlist, which are today-only) because its rows correspond 1:1 to markers drawn on the view you are looking at

- **ErrorBoundary.jsx** — v17.16.0 — the app's ONLY error boundary, mounted in `main.jsx` AROUND `<App/>` (a boundary catches its children, so beside it would compile, review clean and catch nothing — pinned in tests/error-boundary.test.js). Fixes CT-2A-02: there was no boundary anywhere, and React's contract for an uncaught render error is to unmount the WHOLE tree, so any throw in render or in ~30 effects left `#root` empty — a white screen on a tablet mid-service. **`index.html`'s boot watchdog does not cover this**: it fires once at T+10s gated on an EMPTY root, which answers "did the app never mount", not "did it mount and then throw". On its own it fixes no bug; what it does is turn every other throw in the register from an outage into a recoverable state, and the crash test found seven reachable throw sites without looking hard, several from ONE malformed booking the rules will happily store (CT-2A-03). **Two recoveries because they fail differently** — Try again clears `hasError` and restarts WITHOUT re-fetching (the cheap first move for a transient cause; a deterministic one throws straight back, which costs nothing and says something true), Reload app re-fetches from the server. **NEITHER resumes the session**, and the copy must not imply otherwise: React unmounts the errored subtree, so clearing `hasError` is a FRESH MOUNT and every `useState` in `BookingApp` returns to its initializer — measured, 2026-09-07 in List before the crash, today's date in Timeline after Try again. Only the sign-in survives, and that is Firebase auth persistence rather than anything this file does. The first copy promised "it keeps you on the same day", which would have returned a member of staff to today mid-service believing they were still on Saturday's sheet; `tests/error-boundary.test.js` pins the ABSENCE of that promise rather than the wording, because the wording is free to change and the promise is not. The copy says outright that neither fixes malformed data, rather than sending someone round the loop a third time. **Focus, not `role="alert"`**: a live region created already holding its message announces nothing, so the panel is `tabIndex={-1}` and focuses itself via a callback ref. **Its dependencies are deliberately thin** — token scales plus `mkBtn`/`mkSolidBtn`, which return plain style OBJECTS and cannot throw; a surface that renders only once the component tree has failed should not be built out of that tree. `getDerivedStateFromError` tests `typeof error.message === "string"` and NOT truthiness: `new Error()` has a message of "", which is falsy, so a truthy check falls through to the value and renders the bare word "Error" — the exact noise the branch exists to prevent, found by the test rather than in review

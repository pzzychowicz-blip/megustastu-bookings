# src/components — per-file notes

Loads only when Claude works under `src/components/`. Each entry says what the component
is for and the rules a change to it must keep, each with its reason in short. How a rule
was found, with its measurements, is in `REFACTOR_LOG.md` under the version named; how
the code works is in the component. Trimmed to that on 2026-10-27 (the full notes are in
git history, `git show 18f3ee66:src/components/CLAUDE.md`). The visual system is
`DESIGN.md`; app-code architecture and gotchas are `src/CLAUDE.md`.

- **BookingFormModal.jsx** — the booking form, a controlled component (`src/CLAUDE.md`). Phone and NAME autocomplete (`searchGuestsByName`, new bookings only: phone customers collapse by phone, phone-LESS guests are one row per booking and never merge), up to 20 matches scrolling. The Regular / no-show chips reveal past visits ("Regular · N past visits" only at 2 or more). **Guest tags: the form holds TAPS** — chips show `editTagIds(guestTagBase(bookings, editId, {phone, guestId, guestSeed}), form.guestTagEdits)` and a tap is `toggleTagEdit`; the identity is spelled as the save spells it (`enteredPhone(form.phone, phonePrefix)`). `tests/guest-tags.test.js` pins the three calls. Occasion chips edit `form.tags`.

- **TimelineView.jsx** — the Gantt timeline: a horizontal scroller, one row per table, `TimelineBlock`s, waitlist ghosts, the Unplaced row, the now-line.
  - **The block reads left to right, identity then status**: `time · name · size` on the left, a fixed-width rail on the right. **The rail's flags are built ONCE by module-scope `railFlagsOf(b, noShows, warn, currency)`**, read by `TimelineBlock` (draws) and `chipRoomFor` (counts room for the start-time chips); `tests/block-layout.test.js` reads it. Drop order: overstaying `keep`, deposit, zone, repeat no-show, locked, preferred star. **`StatusIcon` leads the rail and is never dropped** (status by colour alone fails WCAG 1.4.1); `STATUS_LABEL` reuses the List's words.
  - **Two traps in the block**: the name span's `flex: 1` ZERO basis is load-bearing (`0 1 auto` shrinks the time chip to "19:0"); and the chip threshold is `chipRoomFor(b, …)`, never a flat width, since rail items do not shrink. Start-time chips are all-or-nothing across the day's CONFIRMED blocks. The double-booked marker and `ClashBand` are FIXED width costs, never droppable flags (a seated block starts a few pixels wide); `chipRoomFor` counts them.
  - **A clash**: a 3px danger border outranking overstay and late, a marker (not the border) telling it apart, and `ClashBand` inside the block, clear of the label and of the border, from the later start to the EARLIER end.
  - **The Unplaced row** sits at the TOP: `unplacedOf(day, gridIds)` packed into lanes (`packLanes`). Load-bearing: `tableForClientY` adds `unplacedH`; the container height is pinned border-box; the FLIP id goes to `primaryGridTable`, never `tables[0]`. A half-placed booking draws on its real rows AND in the row. Its height eases (`unplacedRow`, `held`), and a date change, first load, catch-up or hidden page is a replacement that goes straight there; `useFlip` re-bases every frame while it moves.
  - **Arrivals and departures fade** (`useEnterLeave`, keyed per booking id across the day, `resetKey` = date + first load). A leaving block is drawn from its snapshot, INERT (no handlers, `aria-hidden`, no `data-bk`, no flip id, `pointer-events: none`). A focused block that unmounts hands focus to the grid scroller in a LAYOUT cleanup.
  - **Waitlist ghosts are `TimelineBlock`'s own style object with opacity turned down**: a quieter X dims X, never re-specifies it (an inverting text token changed colour on a theme flip). Hover-lift under its own `data-wg`, never `data-bk` (ids share `genId()`'s namespace). The `⏳` sits before the name so the ellipsis cannot eat it. **Ghosts leave as they arrive**: the tracked identity is the CELL (waitlist id + table), ONE `useRevealRows` for the grid, `resetKey={date}` mandatory, and a departing cell inert on all four counts (role, `aria-hidden`, `tabIndex` −1, `pointerEvents`).
  - **`role="button"` sits on an INNER wrapper**, with the manual-assign handle a real `<button>` beside it (a button's children are presentational); watch the handle's `boxSizing: content-box`. Enter and Space route through `handleClick` and its `didLong` guard.
  - **A day opens where its bookings are**, once per date (today on the now-line, another day on its first booking), guarded by App's `timelineScrollDateRef` so a remount restores the position. It must also write `scrollPosRef`. An empty non-today day does not mark itself done.
  - The hour label under the now-pill fades (`NOW_PILL_CLEAR`); its condition is inline because `nowInRange` is declared below (TDZ). An off-zone party shows `AlertIcon` in the zone slot (`offZoneLabel`). Tags are the block's `title` and a spoken clause only; the `title` sits after `aria-hidden`, which `tests/a11y.test.js` reads as a pair with `data-bk`. Group hover across a multi-table booking is a DOM class toggle, not state.

- **ListView.jsx** — the card list. **The CARD opens the edit form**, so **every control inside it goes through the local `stopped()` wrapper**, or it does its job AND opens the form. Selecting a card does not bump `listFocusReq` (that counter is for programmatic selection only).
  - One status button (`nextStatusOf`), Assign, No show when due and ⋯ (`QuickStatusPopup` with `startArmed`, since a click-opened popup has no held finger). No show sits LEFT of the right-anchored group so the others never move.
  - **Columns are measured widths** (`STATUS_COL`, `NEXT_COL`, `FLAGS_MIN`, `NAME_LINE`; re-measure if the font or badge padding changes). The name column is the day's widest name (`nameColFor(day)`, measured on a canvas, finished cards included, on `dayAll`, so neither the fold nor a tag filter moves the columns). The row holds TWO items, the name and one box holding covers, status and the flags; flags as a third item could wrap alone. `tests/list-columns.test.js`.
  - **Accessibility**: two real `role="list"`s, cards `role="listitem"` with a composed label. ONE roving tab stop, resolved against the cards actually RENDERED (a card inside the closed fold leaves the list with none). Enter/Space guarded by `e.target === e.currentTarget`. ↑/↓ moves real DOM focus synchronously, latched on success. The card focuses ITSELF with `preventScroll` on mousedown; it cannot `preventDefault` (that kills phone-number selection). Card actions are not renamed per booking (the listitem names the booking; decision pinned in `tests/a11y.test.js`).
  - **An active card leaves as it arrives** (`Reveal` on `ROW_FOLD`, `useRevealRows`, `useLeavingOrder`). The gap is each card's `CARD_GAP` top margin, never a flex `gap`; FLIP is quiet while a card folds and for the prune after; the finished list calls `renderCard(b)`, never `.map(renderCard)` (the index would be the gap).
  - A table the layout does not have is a DASHED pill (`TBadge missing`, from App's `missingTables`). A completed card shows "stayed N min" from `stayedMins(b)`, or nothing when it returns null. Tags are `TextFlag` words through `bookingTags`; the tag filter state is App's (`tagFilter`), and App's `listDaySorted` makes the same call so ↑/↓ skip hidden cards. `focusReq` scrolls a programmatically selected card into view on a retry schedule.

- **LateBanner.jsx** — the "Running late" section: one row per today's late confirmed booking (`BannerRows`), per-row ✕ (App's dismissal Set; List and Timeline keep the unfiltered `lateMap`). No show → `doCancelBooking(id, true)`.

- **BannerRows.jsx** — the shared per-row lifecycle (`useRevealRows`) for the row sections, taking `renderRow(id)`. **It renders ROWS ONLY**: the pane, header and collapse are `NotificationStrip`'s, so one collapse bounds the strip's total height.

- **UnplacedBanner.jsx** — the strip's "Not on the grid" section, from App's `unplacedItems` (`unplacedOf`, the one rule the row, this section and the Summary share). Each row names its reason (`unplacedPhrase`) and offers Assign (`setManualTarget`). Scoped to the VIEWED date. **No ✕**: it clears itself when the booking is placed, and dismissing it would hide what it exists to show. Its mark is `UnplacedIcon`, dashed (dashes mean "not really there").

- **ClashBanner.jsx** — double-bookings, one row per clashing PAIR (`findClashes`). Overlap warnings are an OVERSTAY detector and never saw two confirmed bookings on one table, and the reconciler leaves an all-locked clash alone, so this is the only place one is shown. **Its action is Assign, never Reassign** (`reassignBooking` refuses a locked booking, and a surviving clash is locked by definition). It offers the LATER booking, the reconciler's own tie-break. Scoped to the VIEWED date: its rows match markers on the view.

- **ErrorBoundary.jsx** — the app's ONLY error boundary, mounted in `main.jsx` AROUND `<App/>` (beside it would catch nothing; `tests/error-boundary.test.js`). Try again clears `hasError` without re-fetching; Reload app re-fetches. **Neither resumes the session**: clearing `hasError` is a fresh mount, so the copy must never promise to keep the day (the test pins the absence of that promise). It says plainly that neither fixes malformed data. **Focus, not `role="alert"`** (a region created holding its message announces nothing). **Its dependencies stay thin** (tokens and the style-object builders), since it renders once the tree has failed. `getDerivedStateFromError` tests `typeof error.message === "string"`, not truthiness (`new Error()` has `""`).

- **EmptyDay.jsx** — the empty-day prompt for all three views, at the top of the view's content; Timeline and Plan still draw the room under it. **Renders nothing on a closed day** (the app refuses a booking there; the strip's Closed section is that state). App's `isEmptyDay` is false until `bookingsReady`, or it shows on every cold start (`tests/empty-day.test.js`).

- **UpdateRequired.jsx** — "This device needs refreshing" (the schema gate): an `Overlay` that cannot be dismissed, one Refresh button, at z 350 (above popups, under the refusal toast), not in the modal stack. App ORs `schemaBlocked` into `anyModal`, so the page is inert and shortcuts are silent. Nothing reloads by itself.

- **OverlapBanner.jsx** — overstay warnings on `BannerRows` (per-row Reassign and ✕), behind `overlapWarnEnabled`; dismissals are App's, session-only, reset on a day change.

- **WaitAvailBanner.jsx** — the strip's "table free" section: one row per TODAY's waiting party a table fits (App's `waitAvail`), Book (`bookFromWaitlist`) and ✕, on `BannerRows`.

- **RefusalToast.jsx** — the refusal toast in its own always-mounted layer at the app's root: `position: fixed`, z 400 (above the popups), `pointer-events: none`, its own `role="status"`, so it is never drawn under a modal. App's `flashRefusal` stores the box it floats in (`toastBox`); the timer turns `show` off without clearing text or box, so it fades in place. The pill is atoms' `ToastPill`.

- **StatusToasts.jsx** — the transient-toast layer, rendering only (state stays in `BookingApp`): one-slot priority crossfade, the Undo pill. **Its always-mounted container IS the app's transient live region** (`role="status"`); never make it conditional.

- **AppBanners.jsx** — **exports `appBannerSections(props)`, a FUNCTION, not a component**: `NotificationStrip` needs each section's tone, title and count as DATA to build its collapsed tally and sort by severity. Offline, write error, inefficiency. **The parked-write message and `writeWarning` are INDEPENDENT and both can be live**: the section renders both lines, parked first (with Retry and Discard), the warning with its own Dismiss. They stay ONE section, since the collapsed tally is one mark per section.

- **AlertPanel.jsx** — the strip's section shape for a TITLED LIST (as `InlineAlert` is for one sentence): tinted pane, no border, mark and title in `tone`, `AlertRow` children indented to `NOTIF_GUTTER`. It replaced a shape `DESIGN.md` bans. **Not in `atoms.jsx`** (it imports the strip's geometry, and the strip imports atoms: a cycle). **Not `BannerRows`** (that is an arrival/departure lifecycle; these lists are static). A caller passes a `role` (`ALERT_TONES`), never a tone and a tint, because the PAIRING is what goes wrong.
  - **A collapsible header's toggle is a real `<button type="button" aria-expanded>`** wrapping mark, title and count, with `action` as its SIBLING. **The ROW keeps `onClick` and the button has none** (the chevron in `action` must toggle too; a handler on both toggles twice). Callers pass `expanded`. Hover and press use the strip lid's treatment (`mgt-ac-row`, no inline `background`, which would beat the tint).
  - A WRAPPING header (`onHeaderClick`) gives its title `flex: "1 1 auto"` (with a zero basis the actions never wrap and draw over the title on a phone); a non-wrapping one keeps `flex: 1`.

- **AvailBanner.jsx** — "no tables available" with nearby alternatives, on `AlertPanel` (moved out of atoms for the cycle above). The message is the TITLE, the alternatives rows. **The chip is `TimeChip`, a `<button type="button">`** (exported for the WhatsApp draft card); Enter on it picks the time without saving the form (`activatesItself`). Its fill stays: these chips are actions.

- **SearchPanel.jsx** — Find a booking: `searchBookings` across all dates (upcoming first), tap → jump to the day and focus the card in List (`pendingSelectRef` survives the day reset). Header 🔍 and `/`.
  - **Results are COLUMNS on a tablet** (card `FIND_CARD_W`): date, guests and phone each the widest in the results, measured with `textWidth` in the spans' own fonts; the name the widest name capped at `NAME_CAP`, the one cell that may shrink; status a fixed cell. On a phone (`isMobile`) the row wraps, the name on a 64px BASIS (a zero basis left it a sliver). A tag-matched row shows the matched tags under the name (`matchedTagLabels`); `nameCol` is the wider of name and tag line.
  - Dates in the house shape (`formatDay`), the column wider when a result prints its year (`showsYear`). The Done row folds away while typing on a short screen (`Overlay footerYields`).

- **DaySheet.jsx** — the printable day sheet: print-ONLY DOM portalled to `<body>` (sibling of `#root`), shown by `@media print`, **hard-coded light**. While printing, `document.title` is `mgt-day-sheet-YYYY-MM-DD` (a PDF's name), restored after; a non-canonical date names no day. Tags lead the Notes cell in bold. The deposit line reads ALL the date's bookings, not the table's list (a forfeited deposit is on a cancelled one). It only PRINTS a block's `from`/`to`, so it must not filter blocks (`lib/CLAUDE.md`, `isReadableBlock`).

- **PrintModal.jsx** — the print chooser (Day sheet · Timeline · Both), a lazy chunk opened through App's `openPrint` (modal id `print`). **`TimelineSheet` rides inside this chunk**: the sheet must mount synchronously inside the Print click, so it cannot be a lazy component of its own; the chooser hands it up as `Sheet`.

- **TimelineSheet.jsx** — the printed timeline: print-only, portalled, hard-coded light (`PRINT_FILL`, held to the stylesheet by `tests/print-timeline.test.js`), geometry in percent of the range. **Mounted for ONE print**: App's `doPrint` does `flushSync(setPrintJob)` → `data-print` on `<html>` → `window.print()` inside the click; `afterprint` clears both. It reads the screen's flags (`blockFlags.jsx`) and Unplaced rule; a block draws only the flags it has room for (`fittingFlags`), and the key explains only flags drawn, in each flag's `legend` words. Seated bookings at their BOOKED duration. **Three print rules live in `index.css`**: `print-color-adjust: exact`, a named page for landscape, and `html, body { height: auto; overflow: visible }` (App's inline height stops all pagination).

- **blockFlags.jsx** — `railFlagsOf`, the flags a block carries, so the screen and the print read one list. A plain function in a `.jsx` file (its entries hold icons). A new flag needs a `legend`.

- **Summary.jsx** — the day-summary panel in the date-nav row: covers by hour and shift, today's live status bar, More and Print day sheet in the opened body (`M` opens More from anywhere).
  - **Its place in the row is MEASURED** (App's `useSharesLine`): its basis is its one-line width, its `Reveal` carries `contain: inline-size` so the opened body never counts, and **the headline's basis is its content (`flex: "1 1 auto"`), never a fixed width**, or it breaks its row on a different width than the slot decided on.
  - The deposits line sits outside the `hasData` branch (a day whose only booking was cancelled can still hold a forfeited deposit). `currency` is a scalar prop. Freeing-soon tables print as `TBadge`s through module-scope `FreeingEntry` (never inline); a booking with no table keeps "?" as text.

- **WeekView.jsx** — the "More" popover: Week list, Month calendar, Stats; tap a day to jump. `Overlay anchor="top"` so the mode control does not move with the body, and `AutoHeight watch={mode + "|" + ref}`. Stats' tiles are a grid on `isMobile`. Table usage reads `TIMELINE_TABLES` live (the body is not memoised). Its `ref`/`focus` seed from `viewDate`, so they are guarded with `isReadableDate` (`src/CLAUDE.md`, a stored date becoming `viewDate`).

- **ViewSwitcher.jsx** — one segmented control (`role="group" aria-label="View"`, `SEG_TRACK`, `segStyle`, which Settings' `TabBar` shares). The chosen view is LIFTED, not accent-filled ("+ New" is the only solid blue). Right-click or a 450ms hold opens `SplitMenu`. **The hold timer is cancelled from WINDOW-level pointerup/pointercancel**, since the menu's portalled scrim swallows the button's release; `didLongRef` swallows the trailing click; `beginHold()` runs on the hold. Both gestures are inert when `splitEnabled` is off or on a phone.

- **SplitLayout.jsx** — the two-pane container, purely presentational (it takes the two built view ELEMENTS); works only inside the `shellFixed` layout. Each pane is a non-scrolling FRAME carrying the `flexBasis` around its scroller, which pins the focused pane's corner brackets and makes the flat `4%` hover-lift gutter correct (`src/CLAUDE.md`). The divider: `setPointerCapture` is safe here (no child click targets); primary button only, bail on `buttons === 0`; the ratio commits on pointer-UP; double-click resets; **a press keeps its offset from the rule (`grabRef`)**. On touch its hit area reaches `HIT_PAD` into each pane (`.mgt-split-hit`, coarse pointers only). `DIVIDER` is `SPLIT_DIVIDER_PX`, which App's `tlPaneOk` reads too.

- **QuickStatusPopup.jsx** — the status card a hold opens on a timeline block or plan table, and the List card's ⋯ opens by click. Its scrim and card are atoms' `PopupShell` (shared with `SplitMenu` and PlanView's `TablePopover`); every mount site wraps it in `ModalPresence`, so it animates out, lets taps through while leaving, and its buttons refuse while `leaving`.
  - **A pick calls `skipExit()` before it closes** (the card is gone the frame its result starts); only a dismiss plays the exit. A timeline drag closes it as a hand-off through `ModalPresence`'s `handoff` prop (`quickHandoff`).
  - **The click-opened caller passes `startArmed`**: it skips `useArmAfterRelease` (no held finger), focuses the first button, Escape closes it (a capture listener, stopped, or the global Escape also drops the List selection), and focus returns to ⋯ — a pick hands focus back IN its handler (`handBack()`, after `skipExit()`), before any confirm makes the page inert. `onDelete` adds Delete last. **Every hook sits above `if (!booking) return null`** (`tests/list-card.test.js`).
  - **A hold-opened card is inert until the pointer that opened it is released** (`useArmAfterRelease`): it mounts under the finger mid-hold. Card AND scrim suppress `user-select` and `touch-callout`. Offered statuses follow the gates: pending offers only Confirmed and Cancelled; `seated` is dropped once `seatingClosed`.
  - `omitStatus` / `omitNoShow` leave out what the opener already offers; ListView reads both and its own buttons from ONE module-scope `cardActionsOf(b, late, today, nowMins)`.

- **SplitMenu.jsx** — the two-step split setup (direction → second view) on `PopupShell`. Opening it IS the intent: no confirm step, no Cancel; scrim and Escape are the ways out. **Step 2 offers only the two REMAINING views**: the same view in both panes would fight over App's singleton view state.

- **Icons.jsx** — the app's icon set; its house style is `DESIGN.md`'s.
  - **Every CONTROL mark is drawn here.** Two things stay text, as a category: prose arrows inside sentences, and Shortcuts' keycap labels (they depict the key). Chevrons are ONE shape at four rotations.
  - **In the strip an icon is an IDENTITY**: the collapsed tally is one mark per section, so two sections must never share one (hence `ClashIcon` beside `OverlapIcon`, `UnplacedIcon` dashed). **Check for reuse before drawing**: a marker with the same meaning takes the existing icon.
  - **Judge a new icon RASTERISED at the size it ships at** (a canvas blit magnified), never at 24: several candidates that looked right at 24 read as other glyphs at 14px (`ChairIcon`, `ClashIcon`, `DepositIcon`). An interior shape must stay about 3× the stroke or it fills in. `DepositIcon` is a banknote and **currency-neutral** (a drawn symbol varies per restaurant).
  - **`StatusIcon` is the ONE status → mark source** (List, form, popup, timeline, plan), exported as a COMPONENT, never a map (a const export breaks Fast Refresh). `TrashIcon` is the mark on every Delete and Remove; the inbox imports it from here.
  - A glyph sweep cannot see an HTML entity (`&#8249;`), and replacing a glyph means updating the COPY that names it.

- **NotificationStrip.jsx** — the ONE pane every in-flow notification shares; collapsed it is ONE row however many fire (`sections[0]` and a per-section icon + count tally). `role="region" aria-label="Notifications"`, deliberately NOT a live region (it mounts with its first message); App's `notifAnnounce` speaks.
  - **Severity order lives in App**, and the collapsed row reading `sections[0]` makes "worst first" load-bearing. A section is `{id, tone, tint, icon, title, count, node}`, `icon` a COMPONENT; **a new section needs its own icon**. The tally stays when the strip opens (the lid must not change under the finger). One live section lends the strip its title. The strip owns "Closed this day" and "Couldn't load bookings". `collapseMax` is `lateCollapseMax`.
  - **The expanded BODY is capped at 40vh and scrolls; the lid never moves.** No `padding-inline` gutter: the rows' own inset covers the widest control's hover lift plus the focus ring (re-measure if a wider control joins a row).
  - **`swapKey` (the viewed date): the strip is REPLACED on a date change, not edited** — it re-seeds `useRevealRows` and plays ONE WAAPI height shot on `--t-move`, beside the view's slide. **It cannot be `AutoHeight`** (that chases content every frame and clips the sections' own Reveals). The shot asks `reduceMotionOn()` first; the layout effect returns early on a non-swap commit (it re-renders per keystroke); the height baseline is kept by a passive effect that skips while the animation runs (`offsetHeight` returns interpolated values). The lid fades independently of the body (a collapsed strip has no body). The fade is gated on the rendered text differing.

- **VouchersSettings.jsx** — Settings → Vouchers: issue, search, filter, void, and the default validity. **There is no delete, and the header says why at length**, so nobody "fixes" it. `now` is `useState(() => Date.now())`, never `Date.now()` in render (it fed memo deps); sub-components are module-scope.

- **VoucherPicker.jsx** — the booking form's "Gift voucher" field. **It is a `Fld`, not a panel**, using both of `Fld`'s shapes: unattached the FUNCTION shape labels a real input; attached the ELEMENTS shape makes a named `role="group"`. Its dropdown is `useAcRow`, never a copy; `searchVouchers` offers only OPEN vouchers (an empty query lists all: staff hold the physical voucher). **Attaching is not redeeming**: it writes `voucherCode` only, the ledger is written at completion, so a code with no ledger entry is the meaningful *unsettled* state, and detaching is free. **Not a drafting surface of its own**: `voucherCode` lives in the form draft, covered by the form's baseline, so no `onDirty`. `attachRefusal` lives in `lib/vouchers.js` (a component file exporting a function is a lint error); its five refusals are distinct strings, pinned. A voucher on another live booking is marked (`attachedElsewhere`); a refusal closes the list. `matches` is computed ABOVE the attached-state early return. Buttons keep right with their own `marginLeft: auto`, not a zero-basis spacer.

- **VoucherRedeemModal.jsx** — "how much of the voucher did the bill use?", raised while completing a booking that has one. **THREE exits**: Redeem & complete (defaults to the whole balance), Complete without using it (the unsettled state), and **Escape, which completes NOTHING**. **Write order: the booking completes first, the voucher is redeemed only if that dispatched** (that failure lands in the unsettled state the strip names). In `settle` mode (a booking already completed, from the strip) there is no booking write, so `settleVoucher` skips the status write. The amount is `step={0.01}`.

- **UnsettledBanner.jsx** — the strip section for a completed booking carrying a voucher with no ledger entry. The close-time auto-complete never redeems (nobody is there to answer), so this is where it gets settled. **Scoped to the VIEWED date, not today**, and **the only section with no ✕**: it is unfinished bookkeeping about money and clears itself when recorded. Settle opens the redeem prompt in `settle` mode, behind `voucherRedeem`; the party is in its accessible name only.

- **PhoneField.jsx** — the form's phone field: `CountryPicker` + the number box, CONTROLLED by the one stored string (`lib/phone-countries.js`). **The picker is DERIVED from the string every render**; `chosen` is only a preference for an empty number or a shared code. `raw` holds an incomplete prefix ("+4") until `dialOf` recognises it. No default country: the form seeds `phone: ""` in all four openers. **`withTypedCode` runs on BLUR, only if the box was typed in during that focus (`typedRef`)**, reported as source `"detect"` so the suggestion list stays shut; `onBlur` composes with the caller's. Save and Add to waitlist ask `phoneForSave` for a save by Enter that never blurs (into `f`, never `setForm`). **`foundRef` marks a country the FIELD found**, forgotten when the number is cleared (`numberCleared`: the box HAD digits); a PICKED country stays.

  - **A party leaves as it arrives**: each row a `Reveal` on `shift` through `useRevealRows(ids, date, {speed, instantIn: true})` and `useLeavingOrder`; the row's margin is inside its `Reveal`. The empty line is its own `Reveal`, opened once no row is OPEN and not rendered while anyone waits.

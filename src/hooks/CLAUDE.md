# src/hooks — per-file notes

Loads only when Claude works under `src/hooks/`. Each entry says what the hook is for and
the rules a change to it must keep, each with its reason in short. How a rule was found,
with its measurements, is in `REFACTOR_LOG.md` under the version named; how the code
works is in the hook. Trimmed to that on 2026-10-27 (the full notes are in git history,
`git show 18f3ee66:src/hooks/CLAUDE.md`). The root `CLAUDE.md` holds the write guards and
the Rule of law; `src/CLAUDE.md` holds the app-code architecture and gotchas.

- **usePersistence.js** — bookings and table blocks: the listeners, the write guards, the retry queue, auto-extend, auto-complete after close, `bookingsReady` (false until the FIRST bookings snapshot lands; App's "⟳ Loading bookings…") and the reconnect watchdog. Its pure core is `lib/write-path.js`; the five guards' mechanics are in `src/CLAUDE.md`.
  - **Never write inside a `setState` updater** (v17.16.10): `saveBookings`/`saveBlocks` compute from the `bookingsRef`/`blocksRef` mirrors, then `setState` and write as plain statements (the root Gotchas row says why it corrupts data).
  - **Its listeners and heartbeat attach once, with the first render's functions** (v18.3.2). That is safe only because every function an effect reaches reads refs, state setters and imports: a new one keeps to that, or the effect must list it. `tests/stale-closures.test.js` fails otherwise.
  - **A write's `report` rides with it** (`saveBookings(next, isSilent, report)`, v18.4.6): every queued item carries it and `drainPending` hands it back. `landed()` runs once per report (the `LANDED` WeakSet), in the write's `.then` ahead of the `.catch`, and for an empty patch too. The `.catch` clears `lastPatchSigRef` when it is still that patch's, or an identical replay is skipped as a duplicate. `tests/retry-report.test.js`.
  - **An exhausted write is PARKED, never dropped** (`parkedRef`, shown as `parkedWrites`; `retryParked` or `discardParked`). `discardParked` needs no resync, because both callers of `drainPending` set state to server truth just before it. A retry inherits its first attempt's label (`carriedLabel`): the label is filled inside a `setBookings` updater, which has not run when a retry dispatched from a promise callback is parked (v17.16.9).
  - **`readDatabaseRoot()`** (Download backup) rejects with `"offline"` when `!isConnectedRef.current`: an offline root `get()` hangs until the socket returns, where a listened path answers from cache. Read-only, so no write guard.
  - **Reconnect watchdog**: `goOnline(db)` after 20s of a disconnected FOREGROUND page, on the 10s heartbeat, not gated on `navigator.onLine` (`src/CLAUDE.md`, the 5-minute backoff row). `forceReconnect` is the popover's "Reconnect now".

- **usePresence.js** — device presence for the connection-dot popover: one ephemeral `presence/{pushKey}` child per connection, removed by `onDisconnect().remove()`; returns `{devices, myKey, offset}`.
  - **`onDisconnect` alone leaks** (v17.8.0): a drop between arming it and the `set()` landing makes the SDK replay the `set()` on reconnect with no removal armed, an immortal child. So a 45s `lastSeen` heartbeat proves a live connection, a child counts only inside `STALE_MS` (150s), and one past `PRUNE_MS` (10min) is deleted. A child without `lastSeen` falls back to `since`.
  - **Staleness is enforced on READ**, so a leak hides with no write needing to land; deleting is four times more conservative because hiding is reversible and deleting is not.
  - **The prune is ARMED on connect and CONSUMED by the next `presence` snapshot**: in the `.info/connected` handler no snapshot exists yet. `.info/serverTimeOffset` is read because the model compares a server timestamp with local time.
  - Exempt from the CAS rule (the root Rule of law's ephemeral shape); its grant is `presence/$key` `auth != null`, needed since the root `.write` went (v17.16.7).

- **useReminders.jsx** — reminder state, listeners and banner JSX: **the only hook that returns JSX**, so a sweep of `src/components` misses its banner. Ref-mirror saves on a rev pair. It owns `reminderBaseline`/`reminderDirty` for the unsaved-changes guard, diffed through `flatReminder()` (a nested draft must be flattened before `sameDraft`). Which surface is open (`reminderEditor`, `confirmReminderDel`) is App's modal stack, passed in (v17.14.0); the baseline and the save path stay here.

- **useNowMins.js** — the 15s clock tick.

- **useAutoOptimizer.js** — the optimizer thermostat and its daily reset (cutoff and auto-switch from `useOptimizerSettings`).

- **useWalkin.js** — the walk-in draft and its handlers. The record it writes is `walkinBooking` (`lib/booking-save.js`). `doSaveWalkin` keeps the commit-once guard, both refusals, the write (`prev.concat([nb])`, which `tests/submit-guard.test.js` reads) and the close. `walkinBaseline` is STATE set in `openWalkin` only (→ `walkinDirty`). Visibility (`showWalkin`) is App's modal stack; the draft stays here.

- **useWinW.js** — the viewport width.

- **useKeyboardInset.js** — `{ bottom, top }`: how much of a full-screen fixed box the on-screen keyboard covers, and (`coveredTopOf`) how far iOS moved such a box above the visible area, which only the WhatsApp panel pads by. **`Overlay` is its one caller and applies both as PADDING, never by moving an edge** (`src/components/CLAUDE.md`, atoms). The arithmetic is the pure `keyboardInsetOf(win)`, tested with device numbers in `tests/keyboard-inset.test.js`.
  - **The inset is `clientHeight − visualViewport.height − offsetTop`** (`viewportTopOf`). Never read `innerHeight` (iOS moves it apart from the viewport; the test fails if the hook does), and use `offsetTop`, not `pageTop` (a fixed box is laid out in the layout viewport). Each step's device measurements: `src/CLAUDE.md`, the on-screen keyboard row.
  - A gap of `KB_MIN` (100) or less is browser chrome and reads 0. **On Android it is always 0**, by design (`interactive-widget=resizes-content`); a layout that must react to the keyboard asks `useShortViewport`.
  - State is replaced only when a number changes (iOS fires `scroll` per frame). It is seeded by a read at mount, and the effect measures once on subscribing, for an event lost in between. Its `resize` update lands a frame late since React 19.3 (`src/CLAUDE.md` row).

- **useWindowAtTop.js** — puts the WINDOW back at scrollY 0 once the keyboard is down: iOS leaves it scrolled with Lock navigation off, and a dialog opened then paints short while it hit-tests whole (`src/CLAUDE.md` row). Mounted once in `BookingApp`; `windowStrayOf(win)` is the pure predicate and shares `KB_MIN`. **It must not act while the keyboard is up**: that scroll is how iOS shows the field.

- **useShortViewport.js** — `visualViewport.height < SHORT_VIEWPORT` (480): "the keyboard is up and room is short" on BOTH platforms, where the inset is 0 on Android. A height, not "a keyboard is up", so an iPad in portrait reads false. No `visualViewport` reads false; `innerHeight` is not read. The pure `shortViewportOf(win)` is tested in `tests/short-viewport.test.js`. Callers: `InboxPanel`, `Overlay`.

- **useSharesLine.js** — `{ same, settled }`: does flex item `b` sit on item `a`'s line in a wrapping row. It gates `DATE_CTRL_DROP`, and it MEASURES because where an item wraps depends on its siblings' content (`src/CLAUDE.md`, the wrapping flex row). `sharesLine` compares `offsetTop`s, which ignore transforms, so the drop never feeds back into its own gate. One ResizeObserver, on the row. **`settled` is false for the first measurement only**, and callers keep `transition: none` until then, or the first style change animates on load. Unchanged state returns the same object, so a row resizing every frame does not re-render the app.

- **useThemeMode.js** — resolves dark mode (the pref → `isDark`, writes `data-theme`) and rewrites BOTH `meta[name="theme-color"]` to the resolved `--bg-app` through `getComputedStyle` (no colour literal in JS), so the Android PWA's status bar follows the app's theme. Mounted in `BookingApp`, so the login screen keeps `index.html`'s static pair.

- **useOperatingHours.js** — `settings/operatingHours`: per-weekday hours, closed days and special days (`exceptions`, `lib/special-days.js`), fed to the live bindings through `hoursFor(date)` / `setActiveDayHours` (`src/CLAUDE.md`, Operating hours). Week and special days are ONE state (`hoursSig`, App's repaint key for the memoised views) and one ref the savers build on; every write carries both halves and prunes special days 30 days past (`persist`). `saveException` / `removeException` log what they did (`specialDayEntry`); the snapshot hands `exceptionIndex` to `setHourExceptions`.

- **useDayShifts.js** — the Afternoon/Evening split hour → `settings/dayShifts`, clamped to `weekRange()`.

- **useOptimizerSettings.js** — the optimizer cutoff (0–24, full day, decoupled from the hours) and auto-switch → `settings/optimizer`.

- **useBookingDefaults.js** — `settings/bookingDefaults` on a rev pair: the duration tiers (`tiers:[{max,dur}…]`, sorted, at most 6, plus the catch-all `restDur`; feeds `getDur` through `DUR_TIERS`; the legacy flat `t1Max…` shape converts on read), the running-late thresholds, freeing-soon, the banner master switches and the turnaround buffer (drives `setTurnBuffer`). **`turnaroundEnabled` defaults OFF and is sanitised `=== true`**, the inverse of the default-on `!== false` idiom the other switches use.

- **useBackup.js** — "Download backup": `{ backupStatus, doBackup, endBackupOpen }`. One read at a time (`inFlightRef`), and `openRef` ties a read to the open of Settings it belongs to (bumped by `endBackupOpen`, which App's `closeSettings` calls). The flow and every sentence are `runBackup` in `lib/backup.js`, where a report goes is `backupReportTarget`. It asks `refused("dataExport")` first. `tests/backup.test.js`.

- **useAcRow.js** — the autocomplete-row behaviour (`useAcRow()` → `acRowHandlers`) and the menu's geometry (`AC_MENU`, `AC_ROW`) for every dropdown in the booking form, so the tap-versus-scroll logic exists once: **a new dropdown uses this, never a copy.** Select on `onTouchEnd` only if the finger barely moved; suppress the mousedown synthesized after a touch; **never `preventDefault` a `touchstart` or `touchmove`** (React makes them passive, and scroll must stay free). **A TAP cancels its `touchend`**: the pick unmounts the list, and the tap's synthesized click would land on whatever was under it (`src/CLAUDE.md`, the TAP row). The handlers are the pure `acRowHandlersFor(ref, select)`, `tests/ac-row.test.js`.

- **useVouchers.js** — `/vouchers`: the listener and guarded writes, in the `/bookings` shape, because the child key is the voucher NUMBER. So a per-child `updatedAt`/`baseUpdatedAt` CAS applies, written as a multi-path `update()` through `lib/write-path.js` (a voucher's id IS its code: `withId`/`stripId`).
  - **There is no delete**: a `null` reaching the child loop is logged and dropped, because a nulled child frees its number for `generateCode` to re-issue.
  - **Deliberately no client freshness gate and no retry queue**: the server CAS is the protection, and a refused write shows a banner rather than being replayed silently, which for money is the better behaviour.
  - Ref-mirror save, a boolean return so no caller flashes "saved" over a write that never left, `dbError("vouchers")`. Takes `currency` for the log's wording (`voucherWriteEntries`). **Every decision is in `lib/vouchers.js`** (`validateIssue`, `applyRedemption`, `removeRedemption`).

- **useVoucherDefaults.js** — `settings/voucherDefaults` + `voucherDefaultsRev`: `{v, expiryMonths}`, `useBookingDefaults`' shape. **`expiryMonths: 0` means NEVER**, so the clamp floor is 0. Named so, and not `vouchers`, because `/vouchers` is the collection.

- **useTagSettings.js** — `settings/tags` + `tagsRev`: `{ tagList, saveTagList, tagError, clearTagError }`, `useVoucherDefaults`' shape with two differences. **An ABSENT node sets the state back to the seed** (`sanitizeTagList(null)`): a refused write is rolled back by the SDK to the stored value, null for a node never saved, and keeping the state would show a tag nothing holds. **A refused write, or a save before the first read, is said on screen** (`tagError`). `saveTagList(nextList)` takes the whole list, computes from the `listRef` mirror (assigned on the line above each `setTagList`), writes nothing when the list is already as asked, and returns a boolean. Every decision is `lib/tags.js`; `tests/tags.test.js` reads this file.

- **useActivityLog.js** — the activity log's Firebase half.
  - `useActivityLog()` installs `logActivity` as the sink every writer emits into (`lib/activitySink.js`); until it mounts, `emitActivity` is a no-op.
  - **`at: serverTimestamp()`, `uid` and `email` are added HERE and nowhere else**: the rules require all three to be the server's answer, and a client `Date.now()` is refused. **Never use `getUser()`'s "staff" fallback here**: the rules check `auth.token.email`, the refusal would be swallowed by the sink's try/catch, and the entry would vanish. With no signed-in account nothing is written.
  - **`useActivityFeed` is the app's first query** (`orderByChild("at")`, `limitToLast`) and its only non-permanent listener, attached while the log is open. It needs the `.indexOn` in `database.rules.json`. It takes an open range (`from`/`to` may be null) and pages by GROWING one query (`FEED_PAGE` 500, `loadOlder`), never a cursor: `at` ties are routine, and cursor paging must dedupe its boundary row.
  - **Its answer is ONE state keyed to the question**, split into `win` and `limit`: a new window blanks the rows, a bigger limit keeps them. `loading` is DERIVED, never a second boolean, which would need a setState in an effect and could show the previous day's rows under the new date. The limit is keyed to its window and declared BELOW `win` (a `const` TDZ passes build and lint).
  - `clearActivityRange` resolves `{removed, refused}`: nothing matching and the server refusing are different facts. `clearActivityAndLog` writes its "cleared the log" line AFTER the deletes, only if something went. `pruneActivity(windowMs)` defaults WIDER, never to zero. `redactGuest(keys)` takes a list, because `matchesIdentity` spans a phone and every absorbed `guestIds` entry. Erasure and prune are one-shot `get()`s, never `onValue`.

- **useWaitlist.js** — `waitlist`, a whole array on a rev pair: ref-mirror save (the write outside the updater), past dates pruned. `saveWaitlist` is a `useCallback` on `[setWriteWarning]` that reads only refs, setters and imports, so the prune effect can list it.
  - **A party being booked is HELD, not removed** (v18.4.8): `holdEntry` / `releaseEntry` keep per-device ids, and the `waitlist` returned is `withoutHeld` (`lib/waitlist-match.js`), so the panel, the badge and the matcher skip it while saves still compute from the mirror. `doSaveNew` holds before the dispatch, removes in the write's `onLanded`, and releases there and in `onDiscarded`. A reload empties the list.
  - Optional keys are omitted when empty, since Firebase throws on `undefined`: `preference` ("indoor"/"outdoor") and `tags` (ids, through `cleanTagIds`). Neither needed a `SCHEMA` raise: the listener stores entries as they are and every write is the mirror plus a change, so an older build carries an unknown key through.

- **useWhatsApp.js** — the WhatsApp module's listeners and savers; its own header holds the write-guard contract.
  - **Messages are listened to one conversation at a time** (v18.8.0): `watchMessages(phoneKey)` reference-counts `onValue(messages/<key>)` and returns the unwatch. `messagesMap` holds only watched keys, a loading one ABSENT and never `[]`, which ConversationView reads as known-empty. The write guard is per key (`messagesLoadedKeys`): `appendMessage` / `patchMessage` refuse an unread key.
  - **Delete and bulk delete are ONE write** (`deleteConversations` → `conversationDeletePatch`, which `eraseConversation` and `clearAllWaData` use too): rows and messages together, guarded on the conversations read. `eraseConversation` also deletes the number's `waContacts` key.
  - **Draft → booking is two steps**: `takeDraftSource()` reads and clears `draftSourceRef` at the dispatch; `completeDraftAccept` and `linkBookingByPhone` run in the write's `onLanded`, so a dropped write leaves the draft still to accept. An effect clears `draftSourceRef` when the form closes (`formOpen`), so a form closed unsaved credits nothing. It is an effect here because App's `openForm` is declared above `wa`, and reading `wa` there makes the React Compiler skip `BookingApp`.
  - `sendMedia` exists only where `sendsViaServer()` (else null: no paperclip). `handleResend` skips a media message, whose text is only its label.
  - `handleApplyModify` ADDS the requested occasions (`unionTagIds`), never replaces. **App declares `useTagSettings` above this hook**, which reads `tagList`; below it is the TDZ blank screen.
  - The `waContacts` and `waLink` listeners are module-gated with `dbError`; `waLink` is read-only (no browser grant). `draftPrefill`'s name order is typed → phone contact → bookings → profile. **Not a customer** (`handleMute`) sets `muted` with `archived`, and every way out of Archived (`handleUnarchive`) clears `muted`; the unread count skips muted. Simulator writes (`simAppendMessage`, `simSetContacts`) are sandbox-only.

- **useWaUsage.js** — Settings › WhatsApp › Messages and cost: `{status, data, error, load}` from `/api/wa-usage` (`usageViaBackend`). **Asked on demand only, never on mount**: every ask is a Graph call with the restaurant's token. Only the latest ask may answer (`asking`), an answer after unmount is dropped (`live`), and `data` survives a failed ask so the figures stay while the error says why they are old.

- **useWaMedia.js** — one message's file: `useWaMedia(phoneKey, msg, want)` → `{status, url, type, retry}`. `want` says when to fetch; the download and the blob URL are `fetchMedia`'s (`lib/wa-backend.js`), shared per message and released on unmount. `expired` is computed with no request (`mediaExpired`). **"loading" is derived, never set**: an answer is stored keyed to its request (`phoneKey/msgId#attempt`), so the effect's only setState is in the fetch's callbacks. `retry()` bumps the attempt, which is part of the key.

- **useDeferredCompute.js** — `{value, pending}`: runs a heavy compute AFTER a guaranteed paint (rAF → setTimeout, plus a 120ms fallback because a hidden tab fires no rAF), with run-token superseding. **`value` is null while (re-)checking, never a stale answer**, and a result is stored with the deps it answers and read only while they are still the deps (`sameDeps`, `Object.is` per element; otherwise `STALE`), or the last answer stands under the new question for a frame. Used by the form and walk-in availability scans and by `useDraftCheck`.

- **useDraftCheck.js** — `draftAvailability` (`lib/draft-check.js`) for the conversation on screen, through `useDeferredCompute`; keyed on the draft's size, date, time and seating, `bookings`, `tableBlocks`, `autoOptimizer` and `hoursSig`. **Not on `liveBookings`**, which App rebuilds every 15s tick (the card would re-check four times a minute); it is read at scan time.

- **useRecurring.js** — `recurring`: the whole node `{v, enabled, horizonWeeks, rules[]}` on `recurringRev`, ref-mirror save. Occurrences are ordinary `/bookings` children made by App's generator effect (`dueOccurrences`, `withOccurrences`, `lib/recurring.js`).
  - **`enabled` defaults OFF** (`=== true`): the feature and the form's "Repeat weekly" stay hidden until Settings enables it.
  - A rule's optional `startDate` is whitelisted in `sanitizeRule`, omitted when absent; which weeks are due is `dueOccurrences` (strictly after it — root Gotchas, occurrence ids). **Deploy note**: a device on an older build rewrites `recurring` through its own whitelist and drops an unknown rule key from EVERY rule, so a version adding one tells Patryk to refresh every device.
  - `removeRules(ids)` and `setRulesActive(ids, active)` change several rules in one write and return whether it was dispatched (Delete customer). A refused `removeRules` retries itself (`REMOVE_RETRIES` 3) and only the last refusal shows; `saveRecurring(next, isSilent, onRefused)` hands a refusal to `onRefused` in place of the banner.

- **useSchemaGate.js** — reads `/schema` (`{v}`, rev pair `schemaRev`) and hands the number to `lib/schema.js`, which the writers ask; returns `{blocked}` (App shows `UpdateRequired`). Announces this build's `SCHEMA` through `writeWithRev` when the stored one is lower: never before the first read, and **once per page load**, because a refused announce is rolled back and arrives as the old number again. With roles enforced only a manager's or admin's announce is accepted. **Advisory on DEV** (`isDevDb`) unless `localStorage["mgt.schemaEnforce"] = "1"`. **A Vercel preview never announces** (`mayAnnounceFrom`): it is a production build on PROD, and its announce would stop the restaurant's devices for an unmerged branch.

- **useRevealRows.js** — the per-row ease-in/out lifecycle (`renderIds` / `openIds` / prune) behind LateBanner, WaitAvailBanner, the List's active cards and the waitlist's rows.
  - **A replacement is not a change**: on a `resetKey` change, a membership change inside the caller's catch-up window (`opts.quiet`) or one while the page is hidden (`pageHidden`), it re-seeds as on first mount, so a date change or a missed update never folds the old list out under the new heading.
  - **Re-seeds run DURING RENDER**, not in an effect, so the first committed DOM is the new list and the caller's layout effect can measure against it; the ref bookkeeping is in a layout effect. `seenSig` follows every change, so turning `quiet` on re-seeds nothing by itself.
  - The prune's clock starts on the first frame (`afterFrame`), and the `openIds` it returns drops a departed id in the render that loses it, so the fold and its clock start together (DESIGN.md's motion section).

- **useLeavingOrder.js** — `useLeavingOrder(liveIds, renderIds)` → the order to draw a `useRevealRows` list in, each folding row kept where it was (`placeLeaving`, `lib/leaving-order.js`). Kept in STATE adjusted during render, not a ref, since a ref read during render is a React Compiler advisory. Callers: `WaitlistPanel`, `ListView`.

- **useEnterLeave.js** — which timeline blocks ARRIVED and which LEFT: `useEnterLeave(resetKey, deps, capture, {speed})` → `{ leaving, arriving }`. Not `useRevealRows`, whose passive-effect diff would paint an arrival once before its `mgt-appear` class, and cannot draw a departed block as it LAST LOOKED; that needs a render-time diff, held in state.
  - **Its `deps` are compared by identity during render, so each must be stable**: a `= {}` default never settles ("Too many re-renders"). TimelineView's maps default to a frozen `NO_MARKS`, pinned in `tests/motion.test.js`.
  - Holds start on the next frame (`afterFrame`) and clear `exitHold(speed)` after the last change: late is harmless, early is the defect. A diff taken while hidden or under `opts.quiet` re-seeds, like a `resetKey` change.

- **useKeyboardShortcuts.js** — the global shortcuts. App passes ONE ctx object per render, refreshed into a ref by a dep-less effect; the two window listeners mount once. The handler keeps the modifier check, Escape, Enter and the typing guard, then calls `resolveShortcut` (`lib/shortcuts.js`). **Adding a shortcut is a row in `lib/shortcuts.js` plus its `K.<name>` in App's ctx** (`tests/modal-stack.test.js` reads both). Escape acts on `K.topModalId` through `escapeAction(K, id)`, and Enter walks `MODAL_ENTER_ORDER`. **The two orders are deliberately different**: unifying them would be a keyboard behaviour change. A guarded close is named in `escapeAction` (`src/CLAUDE.md`, the unsaved-changes guard).

- **useGeneralSettings.js** — `settings/general` on `generalRev`: the restaurant's name and currency and the ex-hard-coded literals (see the node in Persisted collections below). The seeds are the historical values, and an absent node is a no-op.

- **useUserPrefs.js** — `settings/users/{uid}/prefs`, with `prefsRev` nested inside each `$uid`: the settings that follow the account (`src/CLAUDE.md`, Per-user preferences). **Tri-state: `null` means never chosen**, which the device-fallback seeding depends on, so an absent field is never coerced to `false`. `PREF_SPEC` states each boolean once (its localStorage key and default direction), and only the NON-default value is stored. `theme` stays outside the table (a tri-state string with a `?theme=` override) and takes `"auto"`, stored explicitly because a `null` would be seeded over by the next device to sign in. App width, the Timeline zoom and the split layout stay per-device.

- **useModalStack.js** — ONE ordered stack of open modal surfaces. `MODAL_Z` is the z-order, ascending, and `topModal(stack)` is what Escape acts on (push order only breaks a tie). `applyModal` is the single writer: falsy closes, an updater is applied to the current payload, re-opening an open modal replaces its payload IN PLACE, and an unchanged payload returns the same reference. `modalOpen.<id>` and `setModalFns.<id>` are generated from `MODAL_Z`, and `tests/modal-stack.test.js` fails an id App reads with no rank, and a rank with no `escapeAction` case. **A new modal gets a rank, never its own boolean.**

- **useDismissals.js** — the notification strip's four ✕ Sets: `late`, `overlap`, `wait`, `clash`. The first three are today-only and emptied on a date change (`DAY_DISMISS_KEYS`). **`clash` is absent from that reset on purpose**: it is keyed by pair (`clashRowId`) and PRUNES against the live pairs, so a double-booking can clear and recur. A no-op returns the same object, and an untouched key keeps its Set by reference; downstream memos rely on both.

- **useLayout.js** — `settings/layout` → the live bindings through `setLayout` (`src/CLAUDE.md`, Layout config): tables, zones, join groups, combos, priorities, the floor plan (`sanitizeFloorPlan` places missing tables) and `pickRules`. `defaultLayout()` is the one fallback. Sanitize enforces single-group membership and normalises priorities: a whole-object default when absent, an EMPTY field when present and missing. Refuses an empty-`tables` config.

- **useArmAfterRelease.js** — a surface opened by a PRESS-AND-HOLD is inert until the pointer that opened it is released (`QuickStatusPopup`, `SplitMenu`), or the release activates whatever the finger is resting on. **The signal is the RELEASE, never a delay**, so a short hold and a long one behave the same. Listeners are CAPTURE-phase (the card stops propagation); a new `pointerdown` also arms it; the 2s timeout is only a backstop. **Mount-scoped, which is correct only because every caller mounts its popup conditionally.** A new hold-opened surface takes this hook, never a copy.

- **useReplyDraft.js** — one conversation's WhatsApp reply draft on this device, as a STRING, through `useSyncExternalStore` over `lib/wa-reply-drafts.js` (`draftTextOf`), so a keystroke re-renders the box and that one row (subscribing to the whole store re-rendered every bubble). Read by `ReplyComposer` (which writes with `setReplyDraft`) and each `ConversationRow`. The uid is App's `draftOwner`.

## Persisted collections — what each node is, and who writes it

Moved from the root `CLAUDE.md` on 2026-09-18: every writer named here is a hook in this
directory. Authoritative paths and predicates are `database.rules.json`; the rule for
ADDING a node (a per-child CAS or a rev pair, plus its own `.write` grant) is the root
file's *Rule of law*.

- **`bookings`** — `/bookings/{id}` on the per-child CAS. `sanitize(b, key)` resolves `b.id || key || genId()`: a row keeps its own `id`, and only a row written by something else (the Admin SDK, a console edit) reaches the key arm. The legacy ARRAY arm passes NO key, because an index is a position, not an identity. `genId()` ids are path-safe `[0-9a-z]`. A new per-booking field joins every place the root Gotchas row names.
- **`vouchers`** — `/vouchers/{CODE}`: the code is the child key, so a number exists at most once. Per-child CAS, written by `useVouchers.js`. **A voucher is never DELETED, only voided**, at three layers: no delete function, the patch builder drops a `null`, and the rule's `.write` requires `newData.exists()`. That is what lets `generateCode` exclude every code that ever existed. **Never copy `/bookings`' leading `!newData.exists() ||` disjunct into this rule**: it short-circuits on a delete (an emulator test fails if you do). The ledger is `redemptions/{bookingId}`, so a redemption is idempotent, and `remaining` is RECOMPUTED as `value − redeemedTotal(ledger)`, never decremented. A booking's half is its `voucherCode`, under the booking CAS.
- **`roles` + `invites`** — per-child CAS through `useRoles.js`. A row carries TWO capability maps, `extras` and `denies/{cap}`, objects because rules cannot search an array, with keys SORTED on read for `contentKey`'s key-order-sensitive compare. A level is a default, not a floor: `denies` removes what the level grants, and `setCapability` keeps the two exclusive through `levelGrants(role, cap)`. A deny is a PRESENT `true`, never `false` (the rules test `.val() !== true`). `can()` checks the enforcement flag BEFORE the deny, so a deny stored while experimenting cannot leak through a switch that is off. `isAdminEntry` checks the deny FIRST, as the rule does, or an admin strips their own `settingsAdmin` unseen by `wouldRemoveOwnAdmin`. `GATED_CAPS` is every entry of `CAPABILITIES` (`tests/roles.test.js`). `SETTINGS_TABS.caps` is a LIST and `visibleTabs` tests ANY. `dataExport` has no rule behind it: the backup is built from reads, and `.read` is `auth != null` at the root. No empty-collection guard: `/roles` starts at zero.
- **`activity`** — `/activity/{pushId}`, append-only (the root Rule of law). `useActivityLog.js` adds `at`, `uid` and `email`; `at` must be the `{".sv":"timestamp"}` sentinel. **That clause is in `.write`, NOT `.validate`, on purpose**: `.validate` re-runs over the merged node when a redaction rewrites `subject/name`, so there it would make every entry un-redactable and silently break erasure. Redaction is gated on `customerDelete`. **Guest names are never stored**: the text holds `{b:<id>}` tokens resolved against live bookings, so an anonymised booking reads "Data removed" with no pass over the log; only a DELETED booking's entry carries `subject` and an indexed `guestKey`. `lib/activity.js` decides what an entry says; `lib/activitySink.js` is the hand-off.
- **`tableBlocks`** — a whole array under `tableBlocksRev`. A block's `id` is minted at READ time by `sanitizeBlocks` at BOTH read sites (the listener and `resync()`), and persisted by the next `saveBlocks`. A legacy block's id is DETERMINISTIC from its content (`bl_<hash>_<n>`, the ordinal the first one not already taken, since `hash36` collides), so two reads agree and `removeBlock` cannot become a silent no-op after a resync. Content, never array POSITION. `addBlock` gets a `genId()`. It is a mint, not a whitelist: `reason` is read by `DaySheet` and written by nothing, so a whitelist would drop it.
- **`waitlist`** (`useWaitlist.js`), **`reminders`**, **`reminderFires`** — whole arrays on rev pairs.
- **`recurring`** — `{v, enabled, horizonWeeks, rules[]}` + `recurringRev` (a rule: `id, name, phone, size, weekday, time, preference, notes, active, skipDates, createdAt` and an optional `startDate`; `useRecurring.js`). `enabled` defaults OFF, so an absent node reads as off. Occurrences are ordinary `/bookings` children, NOT stored here.
- **`templates`**, **`conversations`**, **`messages`** — the WhatsApp module (the root Rule of law's Admin-SDK shape). `messages/$phoneKey` is read one conversation at a time. **A message may carry `media: {kind, mediaId, mime?, filename?, voice?, size?}`** (`sanitizeMedia`, `lib/whatsapp.js`), written only by the server, with `text` beside it as the caption or a fallback ("Photo", "Voice message") so an older build still shows a line. The file itself is never stored; Meta holds it 7 days received, 30 sent (`mediaExpired`). A message may also carry `source: "phone"`, `editedAt` / `revokedAt` and `imported: true`; a conversation `muted: true` ("Not a customer"). **None of these needed a `SCHEMA` raise, and why is the test for the next field**: messages and conversations are read without a whitelist and only patched, so an older build cannot delete a key it does not know. A field that a client REWRITES whole, or reads through a whitelist, does owe one.
- **`waContacts`** — `waContacts/{phoneKey}` = `{name, first?, at}`, the restaurant phone's address book as the Business app syncs it (`contactPlan`, `lib/wa-coexist.js`). The phone is the master: MGT never writes a name back. Written by the Admin SDK; the browser's one write is Delete customer's per-key erase (`contactDeletePatch(keys)`, its own `update()`, so a database without this grant still erases the conversation); the inbox's Delete does NOT make it. `conversationName` (`lib/whatsapp.js`) names a conversation by it first. Per-key grant, no CAS, no `SCHEMA` raise.
- **`waLink`** — the Business-app connection (`{status, wabaId, phoneNumberId, connectedAt, connectedBy, contacts, history, phone, lastEvent, disconnect, sim?, measured?}`). **Written only by the server** and given NO grant: its `phoneNumberId` decides which number the webhook accepts. `useWhatsApp` reads it whole for the disconnect banner, the "Not saved on the restaurant phone" hint (only once `contacts.firstAt` is set) and Settings → WhatsApp (`connectionLines`). `measured` is the rehearsal's counts (`api/CLAUDE.md`); `sim: true` marks the simulator's connection.
- **Settings — restaurant-wide config, each on a rev pair and the loaded-ref write guard** (small objects, so the empty-array guard does not apply):
  - `settings/operatingHours` — `{days:{0..6}}` + the special days `{exceptions:{<id>:{from,to,closed,open,close,note}}}` (`useOperatingHours.js`)
  - `settings/dayShifts` — `{split, enabled}` (`useDayShifts.js`)
  - `settings/optimizer` — `{cutoff, autoSwitch}` (`useOptimizerSettings.js`)
  - `settings/layout` — `{tables, joinGroups, comboCaps, megaCombos, kitchenLimit}` + `priorities` (`useLayout.js`)
  - `settings/general` — `{v, restaurantName, currency, phonePrefix, regularMin, lateCollapseMax, waitMatchWin, undoSecs, defaultBookingSize, defaultWalkinSize, phoneCountry, pinnedCountries}` (`useGeneralSettings.js`). `pinnedCountries` is written as `"none"` when empty, because RTDB drops an empty array and absence reads as the seed. `phonePrefix` and `phoneCountry` are no longer written or seeded, and stay in the model because a version still rolling out reads them.
  - `settings/bookingDefaults` — `{v, tiers:[{max,dur}…], restDur, lateEnabled, lateWarnMin, lateNoShowMin, freeSoonEnabled, freeSoonWindow}` (`useBookingDefaults.js`); a present node's missing `tiers` means EMPTY, never the default
  - `settings/voucherDefaults` — `{v, expiryMonths}`, where `0` means never (`useVoucherDefaults.js`). Not `settings/vouchers`: two paths a character apart, one records and one config, is a trap.
  - `settings/tags` — `{v, guest:[{id,label}…], occasion:[{id,label}…]}` (`useTagSettings.js`). A booking stores tag IDS. An ABSENT node reads as the seed; a PRESENT node's missing list is EMPTY, and `v` keeps the node present when both are.
  - `settings/whatsapp` — `{v, autoArchiveOnComplete, autoArchiveSince, autoReply}` (`useWaSettings.js`). `autoReply` defaults ON (`waAutoReplyOn`, `lib/whatsapp.js`, which the webhook asks through `readWaAutoReply`).
  - `settings/admin` — `{v, enforceRoles, modules, activityRetentionDays, waRetentionDays}` + `adminRev`, the ONLY settings node admin-only in the rules unconditionally. It lives in `useRoles.js`, because `can()` is meaningless without the flag. **Every writer sends the WHOLE node through one `writeAdmin(fields)`** merging onto the `adminRef` mirror, which the listener assigns on the line above its `setState`, or one toggle silently resets the others. Both retention values are read through `retentionDaysOf` (`lib/retention.js`), so absent is a year, never the floor; `api/wa-prune.js` reads it the same way, so the screen and the nightly delete agree.
- **`settings/users/{uid}/prefs`** + `prefsRev` (`useUserPrefs.js`) — the one PER-USER node. `localStorage` keeps every pref as a pre-mount cache, and that mirror is load-bearing: `index.html`'s no-flash script reads `mgt-theme` / `mgt-reduce-motion` before React, Firebase or auth resolve. Per-DEVICE settings stay `localStorage`-only.

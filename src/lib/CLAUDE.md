# src/lib — per-file notes

Loads only when Claude works under `src/lib/`. Each entry says what the module is for and
the rules a change to it must keep, each with its reason in short. How a rule was found,
with its measurements, is in `REFACTOR_LOG.md` under the version named; how the code
works is in the module. Trimmed to that on 2026-10-27 (the full notes are in git history,
`git show 18f3ee66:src/lib/CLAUDE.md`). The root `CLAUDE.md` holds the write guards and
the Rule of law; `src/CLAUDE.md` holds the app-code architecture and gotchas.

**Two rules span this directory.** Logic that decides something the restaurant acts on
lives here, pure and tested, never in a `useEffect` or an App handler (v17.8.0; the
plan and apply modules below are that rule applied, each held to the code it replaced
by generated cases). And **the files on the WhatsApp backend's Node ESM chain**
(`whatsapp.js`, `customers.js`, `phone-countries.js`, `tags.js`, `retention.js`,
`wa-coexist.js`, `wa-usage.js`, `wa-mock-media.js`, `draft-check.js`) import with explicit
`.js` extensions, or the backend breaks.

- **booking-logic.js** — the pure core: the optimiser, `sanitize` (re-exported from `booking-fields.js`), derivations, `daySummary`.
  - **`isReadableTime` and `isReadableBlock` are the consumers' requirement, not a format**: kept iff `toMins` yields a finite number, so `"9:30"`, `"13:00:00"` and `":"` keep reading (nothing working may move). A stored time that fails falls back in `sanitize`; `scheduledTime` falls back to the SANITISED time, never the literal.
  - **`isReadableBlock` is exported because two consumers compute with a block's `from`/`to`**: `getBlockSlots` and `TimelineView`'s `BlockBar`. A malformed block is skipped there (the table under-blocked), never defaulted in `sanitizeBlock`, which is a MINT and would persist the default. `DaySheet` and `BlockModal` only print the pair and must not filter (BlockModal is where the block gets removed). `allDay` blocks never read the pair. `tests/booking-logic.test.js` fails a file that hands a block's pair to `toMins` without the predicate.
  - **`optimise` sorts with `id` as a fifth key**, a total order, so two devices place a tied day the same way; `genId()` ids are creation order.
  - **One time axis**: `pastCloseMins`, `seatedElapsed` (capped at that day's close, a cap and not a skip, so the live and frozen figures meet), `seatedIsLive` (the cap bounds the VALUE; only a live booking's duration may be WRITTEN), `liveBarDur`, `occupancyEnd`, `lateMins` all take `today`. `lateState` keeps its date filter (lateness is unbounded backwards), `freeingSoon` does not (self-bounded). `applySeatedShift` refuses a shift outside `[0,1440)` of the booking's own date, BOTH bounds (a booking seated a day early projects `now` negative).
  - **`bookingsAfterAction` returns its INPUT array when the pass moved nothing**, compared on `undoKey`'s field set, so a caller can test identity and an effect cannot loop (`src/CLAUDE.md` row). Callers treat the result as immutable: it may be their own input.
  - **`undoKey` caret-escapes `\u001b`–`\u001f` in every value**: escape, never strip (stripping opens the same collision a character away). `dayBookingsSig` uses `undoKey`'s field set, never narrower than the transform it gates.
  - `findClashes(list, date)` → the PAIRS (`findConflicts` derives from it; `verifyClean` keeps its own short-circuiting copy). Unbuffered. **A pair's `tables` can be EMPTY** (two bookings each taking two tables of one join cluster of four), so callers must not assume a table to name. `clashRowId(pair)` is one clash's identity, separator the `\u001f` ESCAPE (never the raw byte); it lives here because a component file exporting a function fails `react-refresh/only-export-components`. `mergeSpans` merges touching ranges too.
  - **`tablesKept(orig, draft, hasManual, cleared)`** is the one question the save, the availability scan and the Tables row ask (`tablesPinned` by status, or `keepsHandTables`); `blockedTablesAt` / `handKeptRefusal` are a kept booking's refusals (`src/CLAUDE.md`, editing a placed booking). `walkinRefusal` is the walk-in's closed-day and past-close refusal; `seatingClosed` is DEFINED as `pastCloseMins(...) !== null`.
  - `describeBooking(b, {tables})` is the ONE spoken description (List, timeline, plan; Plan passes the table option). State clauses stay at the call site. `plannedDuration(b)` is what was BOOKED; read it, never `duration`, for that question. `stayedMins(b)` is a completed booking's actual stay, from the `stayedMin` stamp App writes on a real seated → completed transition only. `firstStartOf`, `nextStatusOf`, `startingPhrase` (the other bookings, while the kitchen threshold counts the draft). `seatNoteFor(prev, next, b, tags)` is the one seat-note predicate (only a move INTO seated; `time` = `scheduledTime`).
  - **`countLabel(n, one, many)` / `guestsLabel(n)`**: every count on screen, number and word joined by U+00A0. `tests/count-label.test.js` fails `n + " word"` and the plural ternary anywhere in `src/` but its listed records; **never define a local `guestsLabel`** (one shadowed the import across a component; `tests/party-size.test.js`). `phoneForSave` is the phone rule Save and Add to waitlist share (`NO_CODE_REFUSAL`; `untouched` exempts an edit leaving the stored number). `depositSummary` / `depositParts` / `depositLine` (forfeited on a cancelled booking, held otherwise).

- **booking-fields.js** — `BOOKING_FIELDS`, one row per STORED booking field: how a read normalises it (`read`), whether undo and the day signature compare it (`undo`), its history clause (`clause`) and the edit form's seed (`draft`). `UNDO_FIELDS`, `diffBooking` and `draftFromBooking` derive from it; **`sanitize` is a hand-written literal with one line per row, for speed**, held to the loop `sanitizeByTable`, so a new row needs its line there too. **Row order is stored key order** (`contentKey` compares it): append, never reorder. **It imports leaves only** (`booking-logic.js` imports it). The builders that WRITE a booking stay explicit (`booking-save.js`); the root Gotchas row on a new field says what `tests/booking-fields.test.js` asks. `guestTags` / `guestTagsAt` are flat fields because `undoKey` serialises arrays and scalars only.

- **booking-save.js** — the form's save as a PLAN, out of App: `applyEdit` (`doSaveEdit`'s decisions: `{refusal}` or `{next, fin, changed, flash, seatNote}`) and `buildBooking` (`doSaveNew`'s: `{refusal}` or `{next, fin, id, rule, flash}`). App runs the effects in their old order.
  - **`next` keeps the replay contract** (v15.7.0): intent captured once, replayed on whatever `prev` arrives, memoised by `prev` (`memoByPrev`); `buildBooking`'s `id` is minted once so a replay cannot add twice; `genId` and `getUser` run in the old order, which ids and history stamps depend on. `buildBooking`'s `rule` is written in the booking write's `onLanded`.
  - `draftForSave`, `draftRefusal` (name, phone, date, time, unreadable time, closed day, hours, last start, in that order), `formSeatClash`, `kitchenAsk`: what Save decides before it reaches the day. `pickedRefusal` checks the hand-picked tables (`PICKED_REFUSAL`) and is asked by the scan and before the kitchen confirm. `goneRefusal(id, list)` is the `replayRefusal` for a change to one booking. A save whose booking is gone is refused first (`DELETED_REFUSAL`).
  - `editWindow(orig, draft)` is the clock-free part of an edit's window; `keptRefusal` reads it, for the form's availability line. `releaseSwapped` is what a Swap leaves the party it takes from, asked by both saves, `planAssign` and `planDrop`. The displacement refusal is shared by both saves.
  - **`walkinBooking` and `occurrenceBooking`** are the app's other two new records; `occurrenceBooking` owns the deterministic `r<rule>_<date>` id (the root row on occurrence ids). `waitlistEntry(f, opts)` is the entry all three Add to waitlist doors write. `againDraft(source, ctx)` is Book Again's draft, built on `EMPTY_FORM` (no note, deposit or occasion tag).
  - Tags: `applyEdit` and `buildBooking` write `tags: cleanTagIds(f.tags)` and call `saveGuestTags` on `prev` inside the transform, with one `tagNow` taken outside it. `occurrenceBooking` writes both arrays empty; `walkinBooking` neither. Not on the backend's Node chain.

- **constants.js** — the tokens (`S`, `BTN`, `R`, `M`, …; DESIGN.md), the layout and hours live bindings and their setters (`src/CLAUDE.md`, Operating hours and Layout config), `DUR_TIERS`/`setDurTiers`, `TURN_BUFFER`/`setTurnBuffer` (0 = off, the default), `PICK_RULES`.
  - **`EMPTY_FORM.date` is a GETTER**, so a tablet left open past midnight does not default to yesterday; spread and `Object.assign` read it, so callers still get a string. `EMPTY_FORM` is held to `draftFromBooking`'s keys plus `repeatWeekly` (`tests/booking-fields.test.js`).
  - **`exitHold(speed)`** (with `EXIT_PAD`) is how long a leaving node stays mounted, as arithmetic; `EXIT_MS` and `REVEAL_EXIT_MS` are its two applications. `M.dur` is the one hand-kept mirror of the CSS durations (`tests/motion.test.js`).

- **phone-countries.js** — the calling codes (a static list: CSP and offline rule out fetching) and the phone field as a VIEW of one stored string: `splitPhone`, `joinPhone`. **The stored shape never splits** (a new per-booking field, and every customer re-keyed); `tests/phone-countries.test.js` pins that a round trip keeps the `normalizePhone` identity. Longest code wins; `joinPhone` stores `""` for a number with no digits; both trim only LEADING space (they run per keystroke). No default country (`iso: null`). `phoneHasCode` is what Save asks. `withTypedCode(phone, pinned)` is narrow on purpose (pinned codes only, 11+ digits, no leading 0, never +1). `withoutHomeZero` drops a 0 typed after a code except `KEEPS_ZERO`'s, in ONE pass; UK mobiles typed the home way get +44 (mobiles only: landlines share a shape with others). New input only: stored identities do not move. `numberCleared(before, after)` is the one condition on which `PhoneField` forgets a found country.

- **plan-avail.js** — `nextBusyAt` / `freeWindow(…, needMins)` → `{until, fits}`: how long a table stays free from the Plan's minute. PlanView reads it for the availability rim AND the "Walk-in here" gate, so the two cannot disagree. `tests/plan-avail.test.js`.

- **plan-zoom.js** — the Plan's zoom and pan LIMITS: `bandZoom` (a pinch, rubber-banded past `ZOOM_MIN`/`ZOOM_MAX` in log-zoom, at most ×1.25), `clampZoom` (the hard range), `clampPan` (keeps `PAN_KEEP` of the view covered). **Pure and when-free**: PlanView decides where each applies (the band during a pinch only); wiring pinned in `tests/plan-gestures.test.js`.

- **tab-rows.js** — `tabColumns(…)`: Settings' tab bar as one row if it fits, else the fewest balanced rows of equal cells sized to the widest label in bold. The one-row test adds the most any ONE label gains in bold, so choosing a tab cannot flip the layout. `tests/tab-rows.test.js`.

- **reminders.js** — reminder helpers (validate, fire window, prune).

- **recurring.js** — `sanitizeRule`, `sanitizeRecurring`, the whitelist over `recurring` (a key missing from it is deleted by the next write, from every rule). `dueOccurrences(rules, bookings, today, horizonDays)`: active rules' weekdays across the horizon, **STRICTLY AFTER the rule's start** (the cross-device half of the root row on occurrence ids), minus skips, closed days, a time outside `open … lastStartMins(close)` and occurrences already stamped. `ruleStart` is `startDate`, else the earliest booking the FORM stamped, else null. `withOccurrences(prev, due, blocks, autoOptimizer)` is the generator write's transform (re-asks existence against `prev`, since a replay gets a different one). `rulesOfCustomer` is what Delete customer removes. `tests/recurring.test.js`.

- **waitlist-match.js** — `placeWaitlist(...)`: which table the app offers each waiting party. **Sequential and first-come-first-served** (`createdAt` ascending): each party that lands is a synthetic `_locked` hold the next scan sees, or parties are offered the same table at the same minute. `_locked` is load-bearing (`applyOpt` copies a locked booking through). A carried-forward answer is held too. An entry's `preference` is honoured STRICTLY (a `trialFits` answer outside the zone is no offer). `withoutHeld(list, heldIds)` returns the list itself when nothing is held. App keeps only the React parts. `tests/waitlist-match.test.js`.

- **reconcile.js** — the post-sync reconciliation decision: `dirtyDates`, `reconcile(prev, dirty, blocks, autoOptimizer)` → `{next, changed}`. **`next === prev` when nothing moved is the CONTRACT** (an all-locked clash otherwise loops forever), and the manual branch BREAKS when a pass returns its input. `tests/reconcile.test.js`.

- **crash-report.js** — what one crash leaves in `activity` (`crashEntry(thrown, ctx)` → null for noise, or `{signature, entry}`) and whether to write it (`crashGate()`: one entry per signature, five per page load). **`.read` is `auth != null`, so no guest data goes in**: the stack is a whitelist of frames, the digit mask is the message's alone (a minified column can be six digits, and the columns are what gets decoded), a quoted value is masked from its first quote to its last (V8 prints a short unreadable text whole, quotes included), and a thrown object that is not an Error contributes nothing, because a rejected booking's `.name` is a guest's. A thrown string is read through the mask, which cannot see a name, so reject with an Error. `noteCrashView` keeps the view, since `main.jsx` sits above the tree that held it.

- **presence-state.js** — `presenceState(node, now, myKey, canPrune)` → `{devices, prunable, mySince}`, and `deviceLabel(ua)`, the cosmetic "Mac · Chrome" (each chain's order matters: an iPhone's agent says Mac OS X, an Edge's says Chrome). **Hiding is free and reversible, deleting is not**: `PRUNE_MS` is 4× `STALE_MS`, the prune refuses without a real server-clock offset (a fast clock would make every child look ancient), and a child with no usable timestamp is hidden, never pruned. `mySince` keeps `since` verbatim across beats. `tests/presence-state.test.js`.

- **time-grid.js** — `hourLabel(h)` / `hourLabelAt(mins)` (different UNITS) / `isHourMark`. **Settings' `cutoffLabel` is NOT a copy**: it renders 24 as `"24:00"`, where 0 and 24 mean different things; merging them ships a settings bug. TimelineView and TimeAxis are deliberately not unified (percent versus pixels). `spanZoom(gridMins, maxZoom)` is the timeline's opening zoom: 1× for the default 600-minute day by construction, rounded to the zoom control's 0.5 step, within 1…`maxZoom`. `tests/time-grid.test.js`.

- **day.js** — **what day it is** (`todayStr()`, LOCAL, never `toISOString().slice(0,10)`, which is UTC and files the Canaries' first summer hour under yesterday) and **how now and a booking share an axis** (`nowOn(dateStr, today, nowMins)`), plus `dayDiff`, `addDays`.
  - **It imports NOTHING**: `constants.js` needs `todayStr` and `booking-logic.js` imports `constants.js`; a helper needing a live binding goes in `booking-logic.js`.
  - A date-only string parses as UTC midnight, so `getUTCDay()` on it is right and `Date.parse` differences are exact days (DST-proof). Step dates with `addDays`, never `setDate(getDate()+n)`.
  - **`stepDate` is the safe step and `addDays` stays STRICT** (it throws where `stepDate` absorbs; `tests/day.test.js` pins both, so they cannot be collapsed). `isReadableDate` is DEFINED as a zero-day step succeeding, not a pattern (`"2026-8-3"` must keep navigating); `stepUTC` tests its OUTPUT. A bad date anchors on today rather than refusing, so the bad booking stays reachable to repair.
  - **`formatDay(d, {weekday, year, today})` is the house date** ("Thu 24.09"), weekday and day joined by U+00A0; a non-canonical date comes back AS STORED, never `""`. `showsYear` is the one year decision. `weekdayShort` returns `""` for a non-canonical date (the `typeof` guard: `new Date(null)` is a Thursday); `WEEKDAY_SHORT` is imported, never copied. `localDay(at)` is for an INSTANT only. `formatDaysIn(text)` rewrites canonical dates inside stored text on the way out, word-bounded so occurrence ids are untouched; records and the CSV keep ISO. `dayRangeMs` returns null, never a NaN window.

- **write-path.js** — the pure core of the bookings write: `contentKey` / `bookingChanged`, `stampForWrite`, `buildPatch(prev, computed, lastStamp, nowMs)` → `{patch, lastStamp}` (the stamp is THREADED; the ref stays in the hook), `patchSignature` / `isDuplicatePatch`, `isStaleGap`, `writeGate` (which gate stops a write: `{verdict, gate}`), `retryDecision`, `replayOutcome` (refuse with `replayRefusal(prev)` first, else retry, else park), `tellDiscarded` (`onDiscarded` once, never for a report that landed), `changedIds`, `describeWrite`, and `STALE_GAP_MS` / `MAX_RETRIES` / `DEDUPE_WINDOW_MS`.
  - **A patch signature is `(content, baseUpdatedAt)` per child** (CT-2A-08): two patches sharing one are indistinguishable to the server, which is why swallowing one is safe. **`baseUpdatedAt` must never leave the signature.**
  - **`changedIds` and `buildPatch` read ONE pass, `diffChanged`**, whose `byId` holds only the CHANGED occurrences (a last-wins map silently drops an edit on a duplicate id). An equivalence test on a diff compares VALUES, not key sets.
  - **`writeGate` holds the gates' ORDER**, and a fact a caller does not pass is a gate that caller does not ask: the hook asks in two halves (before `next` runs, and with `computed`), `saveBlocks` asks three. `gap` is named apart from `stale` because the caller has a `gapTrip()` to run on it. **Neither half passes both `stale` and `loaded`**, so the order across that join is the hook's call order; `tests/write-path.test.js` holds the function's own.
  - **`describeWrite` reads `prev` over `computed`** (a parked write was undone; the card shows the previous version), names `report.subject` first, and is deliberately not `describeBooking` (it must IDENTIFY in one line).
  - What did not move here, deliberately: the refs, listeners, effects and every `setState` (they stay in `usePersistence`). `tests/write-path.test.js`.

- **submitGuard.js** — **one open of a form produces at most ONE create**: `READY` / `DISPATCHED` + `mayDispatch(state)`, in a ref, checked in FOUR places (`doSave`, `doSaveWalkin` and their button wrappers `save` / `saveWalkin`, which can raise the kitchen confirm first). `disabled` is NOT the fix: `Overlay` keeps the Save button mounted and hit-testable through its exit. CHECK at the top, before validation; ARM only on the line that closes the form after the dispatch; RESET on OPEN only (`openForm` / `openWalkin`). No time window. `mayDispatch` is `!== DISPATCHED`, so it FAILS OPEN. `tests/submit-guard.test.js`.

- **clamp.js** — `clampStep(n, def, min, max, step)`, the settings sanitisers' one primitive. **The NaN check comes AFTER the round** (NaN survives the round and would escape the bounds). `null` and `""` clamp to `min`, not `def` (`tests/clamp.test.js` says so first).

- **modal-keys.js** — what Escape and Enter do to the topmost modal: `escapeAction(K, id)`, `enterAction(K, id, e)` and `MODAL_ENTER_ORDER`, which is deliberately not `MODAL_Z` reversed. `K` is App's ctx, and a test hands in a recorder (`tests/modal-keys.test.js`). `useKeyboardShortcuts` keeps the listener. **A surface holding a draft names its `requestClose*` here**, or Esc walks past the unsaved-changes guard.

- **keyboard.js** — `isTyping(el)`, the guard every key handler asks first (`SELECT` counts: it owns its letter keys). `activatesItself(el)`: Enter on a focused button, link or button-like role is that element's, asked before any modal's Enter action. `stepPress(apply)`: a stepper acts on pointerdown AND on a `click` with `detail === 0` (the keyboard's). `raisesKeyboard(el)`: a textarea or text-like input, narrower than `isTyping`, for a "make room while typing" site. `tests/keyboard.test.js`.

- **drafts.js** — `sameDraft(a, b)` behind the unsaved-changes guard. Not JSON equality: values normalise to strings, arrays sort, `null`/`undefined`/`""`/`false` are one nothing. A NESTED draft must be flattened first. `tests/drafts.test.js`.

- **dbError.js** — `dbError(path)`, the third argument every `onValue()` passes, and `onDbError(fn)`, so a failed read surfaces (without it a cancelled read fires nothing and the app loads forever). **Every new listener passes it.** A grep for `onValue(` over-counts: this file's prose names it.

- **revGuard.js** — the rev-CAS writer for whole-node collections: `attachRev` / `writeWithRev`, an atomic `update({node, nodeRev: base+1})`. **Its success path is `onDone`, never a `.then` on the returned promise** (a `.catch`-handled promise fulfils on failure too; `tests/rev-guard.test.js`).

- **schema.js** — the minimum schema gate: `SCHEMA` is this build's number, `/schema` the highest announced, `writesBlocked(what)` what the writers ask (`saveBookings` and the migration, `writeWithRev`, `saveVouchers`, `useRoles`' `saveKeyed`). Open by choice: `activity`, `presence`, the WhatsApp nodes, the role stub. **Raise `SCHEMA` only when what is stored changes**: every device on the previous build stops writing until reloaded. `tests/schema.test.js` fingerprints every `sanitize*` and the field list. A rollback of a build that announced N locks out N−1 builds until `/schema` is lowered in the console.

- **operating-hours.js** — `sanitizeDay`, `sanitizeWeek`: the whitelists over `settings/operatingHours.days`, which also read the legacy flat `{open,close}`. The bounds are `clampHours`. `tests/operating-hours.test.js`.

- **special-days.js** — closed days or own hours for a date or a run (≤ `SPECIAL_MAX_DAYS`), with a note. `clampHours` is THE hour bounds (open 06–22, close open+1…25). `sanitizeException` (lenient), `exceptionIndex` (overlaps resolve by earlier `from`, then id, the same on every device), `specialDayRefusal`, `affectedBookings`, `pruneExceptions` (returns its input when nothing goes). **`constants.js` does not import it**: the hook hands the index to `setHourExceptions`. `tests/special-days.test.js`.

- **serviceWorker.js** — the app's half of the offline shell: the `mgt-sw` key and `applyServiceWorker()`. **Per-device localStorage only, never synced**: clearing site data is the escape from a bad worker, and a synced flag would re-enable it. Default ON (only `"0"` stored). `useShellPrefs` registers only once `bookingsReady`, so a build that cannot load its data never caches itself. The `mgt-service-worker` skill holds the rest.

- **customers.js** — the phone-identity layer; customers are DERIVED from bookings (`src/CLAUDE.md`, Customer layer).
  - `normalizePhone` / `formatPhone` / `matchCustomerByPhone` keep the WA contract's names: the WhatsApp module imports them, never copies. **`formatPhone` is the one way a phone is shown** (`tests/phone-format.test.js`). On the Node chain.
  - **Two identity keys, UNIONED, never a fallback**: `identityKey` (phone if real, else `guestId`), `matchesIdentity` / `matchCustomerFor`. **Exception: a booking with its OWN real phone is never reached through a `guestId`** (`hasRealPhone` on both sides), so a mis-join cannot let Delete customer erase a different person; the same predicate drives the form's Regular and no-show chips.
  - `stampGuestSeed` (back-stamps the seed; refuses to re-home a booking already joined) and **`resolveGuestId`** (the seed's group wins over the id minted at pick time), called inside the save's transform, never baked into the record, so a replay re-reads `prev`.
  - `customerIndex` is keyed on `identityKey` and folds a guest group into the phone it later acquired (`guestPhoneAlias`; a `guestId` with two phones takes the smallest, deterministically), so `matchesIdentity` takes `guestIds`. `noShowMap` and `guestTagMap` mirror onto aliased ids; read `nsMap[identityKey(b)] || 0`. `searchGuestsByName` never merges phone-less bookings on name and skips index entries with no phone; UI state keyed on `c.phone` collapses every guest onto `""`. `nameQuery(q)`. `isNoShow` (re-exported from `booking-fields.js`): still cancelled, and the flag or the LATEST of "no show" / "no-show cleared".
  - Guest tags (`src/CLAUDE.md` holds the four rules): `guestTagsOf` is the read, `guestTagBase` what a form starts from, `saveGuestTags` and `rehomeGuestTags` return their input when nothing changes, `bookingTags(b, map, list)` is the ONE read behind every surface, `setCustomerTags` / `customerTagTap` for Settings → Customers. `anonymizeBooking(b)` is what Delete customer leaves (`tests/guest-tags.test.js` holds every field row to wiped or kept).

- **whatsapp.js** — the WhatsApp module's pure helpers, imported by the client and by `api/_lib` (Node chain; the phone primitives are RE-EXPORTED from `customers.js`).
  - **`sanitizeParse(parse)` is the boundary for an LLM answer**: a size, date or time the app cannot use becomes `null` (the consumers' predicates: `isUsableSize`/`isUsableDate`/`isUsableTime` over `isReadableTime`/`isReadableDate`). Both draft builders call it. A schema constrains TYPE only. `clampConfidence` counts through the same three. Occasions go through `cleanTagIds`; a parse without the key stays without it.
  - **One rule each, asked everywhere**: `conversationName` (contact → booking name → profile → number), `isPhoneKey`, `replyUnarchives(conv)` (asked by all four reply writers; `tests/api-handlers.test.js` fails a restatement), `pendingDraftOf(conv)` (the draft a new message merges into; the test fails a site restating `draftStatus === "parsed"`), `threadItems` (the thread as drawn, with day separators; `tests/wa-bubble.test.js`).
  - `conversationDeletePatch` and `contactDeletePatch(keys)` are separate writes (a `waContacts` path in the same atomic update refuses the whole erase on a database without its rules). `mergeDraft`, `draftOccasions`, `requestedOccasions`.
  - Media: `sanitizeMedia(m)` (the id is path-safe for a Graph path; a filename loses control characters for a header), `mediaLabel`, `mediaSnippet`, `mediaExpired` (7 days received, 30 sent), `WA_SEND_TYPES`, `WA_SEND_MAX_BYTES` (under Vercel's request cap), `WA_CAPTION_MAX`. `availabilityReply(lang, {...})` is Suggest's reply text.

- **wa-backend.js** — `fetchMedia(phoneKey, msgId)` downloads through `/api/wa-media` with the staff token and resolves a blob URL, reference-counted per message (`releaseMedia`; revoked `MEDIA_KEEP_MS` after the last release), rejecting with `.kind` (`expired`, `toolarge`, `error`) and dropping the entry so a retry is real. `opensInline(type)`: anything else is saved, never opened. `sendMediaViaBackend` sends the raw body with percent-encoded `X-Caption` / `X-Filename`. **A module the simulator imports must not also be imported by production code** (`wa-backend-sim.js` is the split; `src/CLAUDE.md` row).

- **wa-attach.js** — what the composer does with a picked file: `attachKind`, `attachRefusal`, `fitWithin`, `shrinkPhoto` (every photo redrawn: longest side `PHOTO_MAX_SIDE`, JPEG over white, rotation honoured, metadata dropped). Its canvas is the one `tests/list-columns.test.js` allows beside `textWidth`'s.

- **wa-mock-media.js** — media with no Meta behind it: `SIM_MEDIA`, **`mockMediaId(kind)`, the ONE spelling of a mock id** (`tests/wa-media.test.js` fails any other builder), `simMediaMessage` (own keys only). Imports nothing; in `src/` only the stubbed `wa-backend-sim.js` imports it, so it never reaches a production chunk.

- **wa-coexist.js** — what each coexistence webhook BECOMES, decided once, asked by the server (`api/_lib/coexist-core.js`) and the simulator so a simulated record is stored like a real one: `secondsTs` (Meta's seconds clamped to facts), contacts (`contactPlan` / `contactPatch`: a change older than the stored `at` is none), echoes (`echoRecord`, `echoConvPatch`: snippet and time only forward), edits and deletes, history (`historyRecord`, `historyConvPatch`, `historyRequested`), the connection (`linkAfterEvent`, `disconnectSentence`, `connectionLines`, which decides nothing itself). `tests/api-handlers.test.js`.

- **wa-sim-coexist.js** — the simulator's coexistence events as webhook values, `SIM_EVENTS`, and **`simEventRefusal`, the one rule both halves ask: a real `waLink` (no `sim: true`) is never touched**. Not stubbed in production: only `wa-sim.js` may import it in `src/`, and its `wamid-SIMHIST` marker must be in no built chunk (`tests/wa-sim-not-in-prod.test.js`).

- **wa-connect.js** — the `/wa-connect` page's decisions: `loginOptions`, `signupMessage` (only a `*.facebook.com` message with Meta-shaped ids), `CONNECT_STEPS`, `mergeSteps`, `resultHeadline`. `tests/wa-connect.test.js`.

- **wa-usage.js** — the cost counter's arithmetic, shared with `api/wa-usage.js` (imports nothing): `monthBounds`, `monthOf` (a daily bucket filed by its MIDDLE), `summariseUsage` (Meta's answer is input: junk counts 0), `costLabel`, `FREE_TIER_MONTHLY`. `tests/wa-usage.test.js`.

- **wa-reply-drafts.js** — reply drafts on THIS device only (`mgt-wa-drafts`, `{uid: {phoneKey: {text, at}}}`), never in the database. The pure core returns its input when nothing changes (`useSyncExternalStore` needs that); every storage access is in a try. **Drafts follow the conversations that exist**: the conversations listener calls `keepReplyDraftsFor` with every key it read, so no delete path forgets a draft by hand. `tests/wa-reply-drafts.test.js`.

- **retention.js** — `retentionDaysOf(v)` and its bounds, for both `activityRetentionDays` and `waRetentionDays`. **Imports nothing** (`api/wa-prune.js` reads it under Node). Absent, null, 0 or junk is the shipped year, never the floor.

- **draft-check.js** — does a WhatsApp request fit, before Accept. **The scan is the booking form's own** (`availScan` and `kitchenScan` composed the same way), so the card and the form cannot disagree; `tests/draft-check.test.js` holds each case to `trialFits`. `draftAvailability(...)`: a closed day asks nothing else; a time Save refuses is `outside`, never a fit; the kitchen counts THIS party. **`draftPrefill(conv, bookings, contacts)` is the one rule for name and phone**, read by Accept AND Add to waitlist (message → contact → bookings → profile). `onWaitlistFor` is derived, never stored.

- **holdSelection.js** — `beginHold()`: suppresses the OS text-selection gesture for the DURATION of one of our press-and-holds, by `data-holding` on `<html>` (`html[data-holding] *` in `src/index.css`). **Scoped by time, not by element**: iOS raised the selection UI over the header, far from the held element. **Self-terminating** (capture-phase `once` listeners on every pointer and touch end, plus a 3s backstop), since an attribute stuck on `<html>` makes the app unselectable. At rest nothing changes, which keeps the List card's phone number copyable. Called by `TimelineBlock`, `PlanView` and `ViewSwitcher`; **a new hold gesture calls it too**.

- **activitySink.js** — the module-level hand-off between code that knows something happened and the hook that can write it (`dbError.js`'s shape). A sink makes coverage greppable. **It never lets anything reach its caller** (callers are on the booking write path); no sink is the normal state and is not warned about.

- **activity.js** — what the log SAYS about a write; `at` / `uid` / `email` are added by the hook.
  - **Names are never stored**: a booking's name becomes a `{b:<id>}` token resolved against live bookings, so erasure is a property of the shape; only a DELETED booking's entry carries `subject` and `guestKey`. `rowText(r, byId)` leads a row with the booking's current name.
  - `tokenizeNames` SPLITS strings and never builds a RegExp (a name is free text), longest name first.
  - **`guestKeyOf` IS `identityKey`**, imported, never restated (a mismatch is a missed erasure nobody sees; an agreement test pins it). Optional keys are OMITTED, never `undefined` (Firebase throws, the sink swallows).
  - `settingsWriteEntry` reports a LIST node by its SIZE (an index diff names invisible positions) and returns null when nothing differs. A reshuffle is ONE Automatic row per write. `ACTIVITY_KINDS` and `PRUNE_AFTER_MS` are stated here AND in `database.rules.json`; the tests compare the two. `clearOutcome` / `CLEAR_FAILED` are the Clear button's sentences. `tests/activity.test.js`.

- **backup.js** — `buildBackup(root, meta)`: the WHOLE database as read, verbatim (never sanitised), minus `BACKUP_OMIT` (each omission with its reason), plus `_backup` as the first key. **`tests/backup.test.js` DERIVES its node list from the rules file**, so a new node is swept the day it lands; leaving one out is the decision that gets written down. No "did the read come back whole" check: the SDK is the guarantee, and `readDatabaseRoot` refuses offline. `runBackup` (always resolves) and `backupReportTarget` are the flow; `lib/download.js`'s `saveTextFile` is the DOM half. Restore: `database.rules.README.md`.

- **unplaced.js** — which bookings are not properly on the timeline grid and why: `unplacedReason(b, gridIds)` (`none` · `missing` · `conflict`), `unplacedOf`. **One rule for three surfaces** (the Unplaced row, the strip's section, the Summary's count). Cancelled and completed are never unplaced. **The grid's ids come in as an argument**, never the live binding. `primaryGridTable` (the first table that HAS a row), `packLanes` (greedy by start then id, the same on every device), `unplacedHeight`. `tests/unplaced.test.js`.

- **edge-scroll.js** — the timeline drag's edge scroll: `edgeVelocity` (a ramp inside `EDGE_BAND`, held past the edge), `edgeStep` (carries the fraction), `scrollParentY` (skips the horizontal scroller by SIZE), `scrollBounds` (stops at a `[data-fixed-bottom]` bar). The loop is `TimelineBlock`'s, because the drag's offset must grow by exactly what it scrolled. `tests/timeline-drag.test.js`.

- **focus-return.js** — `openerFor(dialog)`: the element a dialog returns focus to, falling back to a recent `focusout` outside it (`RECENT_MS`), since a lazy, auto-focusing or popup-opened modal has often lost its opener already. **The `focusout` listener installs when the MODULE LOADS**, or the first dialog misses its own opener. Pure core `pickOpener`. `tests/focus-return.test.js`.

- **after-frame.js** — `afterFrame(fn, ms)`: run after the NEXT animation frame. **Every exit hold starts its clock here** (a hold started in an effect after a tap begins before the animation does). No timeout fallback, deliberately. `pageHidden()`: callers for which a change while hidden is a replacement ask it and start no hold (`useEnterLeave`, `useRevealRows`, `Reveal`); `usePresenceLifecycle` does not. `everyFrame(fn)` for TimelineView's re-base loop. `tests/motion.test.js`.

- **leaving-order.js** — `placeLeaving(liveIds, renderIds, prevOrder)`: a folding row goes straight after the nearest row drawn before it last time, runs keep their order, and a live id not yet mounted is left out. It replaces DESIGN.md's `rank - 0.5`, which misplaces the second of two departures. `tests/leaving-order.test.js`.

- **wipe-window.js** — how long a status-change overlay stays mounted, **counted from the moment the overlay MOUNTS** (`armWipe` from its ref callback; idempotent), not from the effect. `pendingWipe`, `wipeOpen`. `tests/wipe-window.test.js`.

- **print-end.js** — `onPrintEnd(onEnd)`: when a print is really over (`afterprint` on desktop; on iOS the first pointer or key event back). `printOrReport(onIgnored)`: a Home Screen app on iOS drops `window.print()`, so it waits `PRINT_IGNORED_MS` for `beforeprint` and reports; it asks the event, never the platform.

- **scroll-lock.js** — `lockPageScroll(doc)`: counts open full-screen surfaces and holds `mgt-scroll-lock` on `<html>` while any is open; an idempotent release. **Never go back to saving and restoring `body.style.overflow`**: the shell owns that.

- **toast-box.js** — `toastBox(rect, viewportWidth)`: the box `RefusalToast` is drawn in. Pure.

- **drop-plan.js** — `planDrop(ctx)`: a timeline drop's conclusion, `null` · `{refuse}` · `{transform, done}`. `liveBookings` decides occupancy and `bookings` is what the displacement trial runs on: separate arguments on purpose. - **manual-assign.js** — `planAssign(ctx)` → `{transform, reshuffles}`, the table picker's Save (re-optimises `viewDate` and the day of any released party elsewhere). `swapSlot` / `liveSwap`: a Swap held by the form until Save is tied to the date, time, size and duration it was picked for. `planReassign(ctx)`: the Overlap banner's Reassign, which moves nobody else. `tests/manual-assign.test.js`.

- **shortcuts.js** — the letter, symbol and arrow shortcuts as a table (`SHORTCUT_LAYERS`, `resolveShortcut(ev, K, env)` → null or `{prevent, act}`). Layers in the old handler's order; within one, the first matching row decides, and a null `run` still ends the lookup. One-character keys are matched lower-cased. - **status-change.js** — `planStatus(ctx)` (a status tap: `{confirmCancel}` · `{voucherAsk}` · `{voucherBack}` · `{refuse}` · `{seatClash}` · `{transform, flashes, flashKind, seatNote}`, in `updateStatus`'s old order), `planCancel(ctx)` (memoised by `prev`: App runs it for the undo delta and `saveBookings` runs it again), `completeCleared(ctx)`. - **voucher-settle.js** — `planSettle`, `settleEffects` (asked AFTER the booking write dispatched), `carryOffer` (the balance less what was just redeemed), `carryTransform` (re-asks `attachedElsewhere` against `prev`). **The ORDER stays in App**: the booking write, then the money, then the offer. `tests/voucher-settle.test.js`.

- **tag-filter.js** — the one read behind the List's tag chips, Customers' chips and Find: `bookingTagIds` (tags as SHOWN), `filterByTags` (returns THE SAME ARRAY when nothing is chosen), `dayTagChips`, `customerTagIds`, `guestTagChoices` (no chip leads to an empty list). - **tags.js** — the tag list, pure, importing nothing.
